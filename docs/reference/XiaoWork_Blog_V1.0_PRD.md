# XiaoWork Blog V1.0 产品需求文档（PRD）

> **文档版本：** V1.0（需求基线）  
> **编制日期：** 2026-10-22  
> **评审状态：** 产品需求基本通过；待技术选型与架构评审  
> **项目阶段：** 需求设计，**尚未开始编码**  
> **项目名称：** XiaoWork Blog（暂定，可通过后台设置修改站点展示名称）

## 1. 项目概述

### 1.1 背景
从零开发并自行部署一套个人博客系统。它不是仅由静态文章组成的网站，而是包含内容发布、后台管理、普通用户账号与评论互动的完整 Web 应用。

### 1.2 产品目标
1. 为访客提供清爽、快速、适合阅读技术文章的博客体验。
2. 为博主提供 Markdown 写作、媒体管理、文章发布和更新能力。
3. 允许用户通过邮箱注册和验证后参与公开评论。
4. 通过本地文件持久化、备份与 Docker 化部署，保证博客可长期维护。
5. 采用模块化设计，为后续功能扩展保留空间，但 V1.0 不过度建设。

### 1.3 产品原则
- **内容优先：** 阅读体验优先于动画和组件数量。
- **前后台职责明确：** 前台负责浏览与互动，后台负责内容、用户、评论和设置管理。
- **发布可靠：** 正在编辑的草稿不得覆盖读者所见的公开版本。
- **安全默认：** 账号、评论、上传与后台接口上线前必须具备基础安全防护。
- **低运维复杂度：** 首版采用模块化单体优先，不要求微服务架构；具体语言、框架、数据库待技术评审。

## 2. 范围与优先级

### 2.1 V1.0 范围（P0，首版交付）
- 现代简约、响应式的双栏博客前台：首页、文章详情、分类、标签、归档、搜索、关于页。
- 左侧简洁个人信息栏：头像、昵称、简介、常用外链图标；PC 与手机自适应。
- Markdown 编辑器、实时预览、草稿自动保存、文章封面与图片插入。
- 文章分类、标签、摘要、Slug、发布、撤回、软删除和回收站。
- **已发布内容与编辑中草稿分离**，由管理员主动执行“发布更新”。
- 邮箱+密码注册、邮箱验证、登录退出、邮件找回密码及个人中心。
- 已验证且登录的普通用户发表评论和回复；评论直接公开，管理员事后管理。
- 本地服务器图片存储、媒体库、上传管理和持久化目录。
- 管理后台：控制台、文章、分类标签、评论、用户、媒体、网站设置。
- 基础 SEO、RSS、Sitemap、友好 URL、明暗主题、移动端适配。
- Docker Compose 部署、配置管理、备份恢复、升级迁移和交付文档。

### 2.2 明确排除（V1.0 不做）
- 第三方登录、社交登录、多管理员协作和复杂 RBAC 权限配置。
- 普通用户投稿、付费/私密文章、定时发布、多人协作和完整历史版本回滚。
- 评论点赞、评论图片、私信、站内消息、实时通知及评论审核队列。
- 相册、项目作品集、音乐播放器、打赏、收藏、好友关系、多语言和 AI 写作。
- 复杂访问分析报表、大规模分布式搜索、微服务拆分及外部对象存储接入。

> “建议纳入”的搜索、归档、分类标签、基础后台、用户中心、SEO 与备份恢复，经本次评审均列入 V1.0 基础范围。任何新增功能均需单独评审，不能默认加入首版。

## 3. 用户角色及权限

| 角色 | 文章浏览/搜索 | 浏览评论 | 发表评论/回复 | 管理自己的评论与资料 | 内容及系统管理 |
|---|---|---|---|---|---|
| 游客 | 是 | 是 | 否 | 否 | 否 |
| 普通用户（邮箱已验证） | 是 | 是 | 是 | 是 | 否 |
| 管理员 | 是 | 是 | 是 | 是 | 是 |

- **待验证账号：** 可以完成邮箱验证或再次请求验证邮件，但未完成验证前不得发表评论。
- **禁用账号：** 禁止登录或继续执行需要身份认证的操作；公开历史评论按管理员处理结果保留或隐藏。
- **管理员账号：** 由受保护的初始化/管理流程创建，不可从公开注册流程获得管理员权限。
- **授权要求：** 服务端逐接口校验角色和资源所有权；仅隐藏前台按钮不构成权限控制。

## 4. 信息架构与前台视觉

### 4.1 公共页面
| 页面 | 作用 | 建议路由（实施时可统一调整） |
|---|---|---|
| 首页 | 最新文章列表、分页和个人信息栏 | `/` |
| 文章详情 | 阅读 Markdown 正文、目录、评论 | `/posts/:slug` |
| 分类/分类详情 | 查看分类及其文章 | `/categories`、`/categories/:slug` |
| 标签/标签详情 | 查看标签及其文章 | `/tags`、`/tags/:slug` |
| 文章归档 | 按年、月浏览 | `/archives` |
| 文章搜索 | 标题、摘要、正文关键词检索 | `/search` |
| 关于页 | 介绍博主，可后台编辑 | `/about` |
| 登录/注册/验证/重置密码 | 用户账号流程 | `/auth/*` |
| 用户中心 | 资料、邮箱与密码、我的评论 | `/account/*` |
| 管理后台 | 内容和站点管理 | `/admin/*` |
| 错误页 | 404 和必要的异常状态提示 | 由路由处理 |

### 4.2 视觉设计（已确认）
- **布局：左侧个人信息栏 + 右侧文章主体**，而不是左侧文章、右侧信息栏。
- **风格：现代简约。** 保持克制的配色、统一留白与圆角、舒适中文排版、轻量动画。
- **个人信息栏：** 头像、昵称、简短介绍，以及 GitHub、邮箱等外部链接图标。后台可设置每个图标的链接、顺序和是否显示。**不堆叠**分类、标签云、天气、音乐、访问统计等小组件。
- **文章区：首页**显示最新文章（标题、摘要、可选封面、分类/标签、日期、阅读量）并分页；**详情页**显示正文、目录、标签、上一篇/下一篇和评论区。
- **导航：** 首页、分类、标签、归档、搜索、关于、登录/用户入口；支持后台调整基础导航项。
- **PC：** 两栏，个人信息栏可随页面滚动保持可见（sticky），但不得遮挡内容。
- **手机：** 单栏，个人信息卡片移至文章列表/正文之前；顶部导航收纳，不出现横向溢出。
- **主题：** 支持亮色、暗色和跟随系统；手动选择可在本地记住。
- **阅读：** 标题目录锚点、代码高亮与复制按钮、图片放大浏览、懒加载、回到顶部、阅读进度提示。
- **无障碍：** 键盘可操作、焦点状态清晰、基本对比度达标、尊重减少动画偏好。

## 5. 功能需求

### 5.1 文章与发布（POST）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| POST-01 | 创建、查询、编辑文章 | 包含标题、正文、摘要、封面、分类、标签、Slug、评论开关及 SEO 字段 |
| POST-02 | Markdown 源码编辑 + 实时预览 | 支持分栏、纯编辑、纯预览；标题、列表、链接、引用、表格、任务列表、代码块、图片 |
| POST-03 | 自动保存编辑草稿 | 异常断开或离开页面前尽量保留工作成果，显示保存状态和未保存提示 |
| POST-04 | 首次发布 | 仅管理员可发布，公开后可在列表、详情、搜索、Sitemap 访问 |
| POST-05 | 公开版本与编辑草稿分离 | 编辑已发布文章不会自动改变线上标题、正文、封面、分类标签和 SEO 内容 |
| POST-06 | 手动“发布更新” | 确认后才替换线上版本；文章 URL 与既有评论保持稳定 |
| POST-07 | 撤回、软删除、回收站与恢复 | 撤回/删除后不再公开；恢复不应未经确认自动重新公开 |
| POST-08 | 分类、标签、归档、分页、搜索 | 每篇文章最多一个主分类，可配置多个标签；默认“未分类”兜底 |
| POST-09 | Slug 管理 | 自动生成且唯一，可手动调整；修改后尽可能保留旧链接重定向 |
| POST-10 | 单篇评论开关 | 关闭后不允许新评论，原有评论默认保留展示 |
| POST-11 | Markdown 导入导出 | 可导入/导出 `.md` 文件，原始 Markdown 为持久化内容格式 |
| POST-12 | 基础 SEO 与文章阅读 | Meta、规范 URL、标题目录、代码高亮、图片预览、上下篇导航 |

**文章字段约束：** 标题与正文为发布必填项；摘要、Slug 可以自动生成，也允许人工覆盖；封面和标签可选。创建时间、首次发布时间、公开更新时间和草稿保存时间须区分。浏览量仅用于基础展示，允许采用去重或统计近似值，不作为财务级精确指标。

**版本模型业务规则：** 新文章只有编辑草稿；首次发布形成公开快照；编辑已发布文章始终写入编辑草稿。点击“发布更新”时将草稿内容及其发布相关元数据一次性切换为新公开版本。评论归属文章实体而不是某一编辑草稿。完整历史回滚不在 V1.0 范围内。

### 5.2 账号与个人中心（AUTH）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| AUTH-01 | 邮箱+密码注册 | 收集昵称、唯一邮箱和密码；有效性校验与防批量注册 |
| AUTH-02 | 邮箱验证 | 新用户收到验证邮件，链接一次性、带有效期；支持受限次数的重新发送 |
| AUTH-03 | 登录、退出及会话 | 认证状态安全维持；登出后会话失效；合理的过期策略 |
| AUTH-04 | 忘记密码与重置 | 通过邮件发送一次性重置链接，成功后旧重置链接失效 |
| AUTH-05 | 用户个人资料 | 查看和修改昵称、头像、简短简介及密码 |
| AUTH-06 | 邮箱修改 | 修改时验证新邮箱，避免未经验证就赋予新邮箱身份 |
| AUTH-07 | 我的评论 | 查看本人发表的评论并删除自己的评论 |
| AUTH-08 | 账号状态与权限 | 管理员可禁用/恢复普通用户；禁止普通用户获取管理员权限 |

**默认安全规则：** 邮箱验证链接有效期建议 24 小时，密码重置链接建议 30 分钟，均应可配置；密码使用强哈希算法存储（如 Argon2id，具体实现技术评审决定）；会话建议使用安全 Cookie 和服务端可失效的会话机制。验证码是否触发可基于请求频率和风险，不强制所有操作都出验证码。

### 5.3 评论与管理（COMMENT）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| COMMENT-01 | 登录且邮箱已验证才能评论 | 游客看到登录引导；待验证用户收到验证提示 |
| COMMENT-02 | 发表评论立即公开 | **不做首评审核和逐条审批队列**；通过合法性检查后直接展示 |
| COMMENT-03 | 回复与楼中楼 | 支持回复指定评论；界面最多两层缩进，保存实际父级/被回复关系 |
| COMMENT-04 | 评论展示与排序 | 昵称、头像、发布时间、内容及回复关系；支持最新/最早、分页 |
| COMMENT-05 | 用户自主管理 | 用户可以删除自己的评论；被回复的已删评论可显示删除占位 |
| COMMENT-06 | 管理员事后管理 | 按文章/用户查找，隐藏、删除评论，禁用违规账号 |
| COMMENT-07 | 单篇评论开关 | 关闭文章评论后禁止新增及回复，默认保留历史内容 |
| COMMENT-08 | 反垃圾与安全 | 请求限流、长度限制、XSS 防护、反机器人措施及违规日志 |

**首版评论格式：** 纯文本、换行、Emoji 及安全链接；不支持用户注入 HTML、上传图片、评论点赞、编辑评论、站内通知或人工审核队列。管理员删除与隐藏属于事后治理，不改变“默认直接公开”的产品决策。

### 5.4 本地媒体管理（MEDIA）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| MEDIA-01 | 文件上传 | 管理员在编辑器或媒体库中选择、拖拽、粘贴上传图片 |
| MEDIA-02 | 本地持久化 | 文件保存在宿主机持久化目录/挂载卷，容器重建不丢失 |
| MEDIA-03 | 元数据记录 | 数据库记录文件标识、相对路径、类型、尺寸、大小、上传时间与引用信息 |
| MEDIA-04 | 文件格式 | JPG、PNG、WebP、GIF；校验实际类型、扩展名、尺寸和体积上限 |
| MEDIA-05 | 媒体库 | 预览、搜索、选择复用、复制地址、删除 |
| MEDIA-06 | 资源关联保护 | 删除文章不连带删除媒体；删除被引用资源需阻止或明确提示 |
| MEDIA-07 | 图片优化 | 合理生成缩略图/压缩静态图片，保留 GIF 动图行为，不得无提示破坏原图 |
| MEDIA-08 | 备份和恢复 | 文件与元数据同时备份、可迁移及恢复；上传目录不可暴露任意脚本执行能力 |

**边界：** V1.0 仅本地存储，不接入 Cloudflare R2 或第三方对象存储。媒体服务设计应避免业务直接依赖绝对磁盘路径，以便将来扩展存储后端。用户头像可通过受限上传入口保存；文章及站点媒体的管理权限仅对管理员开放。

### 5.5 搜索、归档与 SEO（DISCOVER）
- `DISCOVER-01`：只检索**已公开**文章的标题、摘要、正文；支持关键词、空结果、分页和稳定排序。
- `DISCOVER-02`：分类和标签具有独立的可访问列表/详情页；分类标签删除时妥善处理文章关联。
- `DISCOVER-03`：按年、月汇总已公开文章，时间以**首次公开发布时间**或明确的统一口径为准。
- `DISCOVER-04`：为公开文章提供独立标题、描述、规范 URL、Open Graph 等基础 SEO 信息。
- `DISCOVER-05`：提供 Sitemap、robots 规则、RSS；后台、账号私有页、草稿和已撤回内容不得被公开索引。
- `DISCOVER-06`：文章发布、撤回、更新、删除后，同步或最终一致地更新公开搜索结果与 Sitemap。

### 5.6 管理后台（ADMIN）
- `ADMIN-01` **控制台：** 展示文章总数、注册用户数、评论总数、待处理安全/异常提示及近期内容动态；不包含复杂 BI 分析。
- `ADMIN-02` **文章管理：** 列表、搜索、分类/状态筛选、编辑草稿、预览、发布更新、撤回、回收站。
- `ADMIN-03` **分类/标签管理：** 新增、改名、调整顺序、启停或删除与关联处理。
- `ADMIN-04` **评论管理：** 按文章/用户/时间筛选评论、隐藏/恢复、删除、定位违规用户。**无“待审核”流程。**
- `ADMIN-05` **用户管理：** 按昵称/邮箱搜索，查看注册日期、验证与账号状态，禁用/恢复，查看用户评论。
- `ADMIN-06` **媒体管理：** 上传、复用、预览、删除及引用安全检查。
- `ADMIN-07` **站点配置：** 站名、Logo/Favicon、网站简介、左侧个人头像/昵称/简介、外部链接图标及顺序、顶部基础导航、关于页、SEO 默认字段、联系邮箱。
- `ADMIN-08` **安全：** 后台全部接口实施管理员鉴权；危险操作须二次确认，并保留必要操作日志。

## 6. 关键业务流程

### 6.1 文章首次发布
1. 管理员新建文章并填写标题、Markdown 正文及其他可选字段。
2. 编辑器自动保存**未公开草稿**；管理员可预览。
3. 系统检查标题/正文、Slug 唯一性及资源引用。
4. 管理员主动点击“发布”。
5. 系统形成公开版本并记录发布时间，文章出现在前台列表、搜索、归档、RSS/Sitemap 等适用位置。

### 6.2 已发布文章更新
1. 管理员编辑文章，任何改动（包含标题、封面、分类、标签、SEO）只写入独立编辑草稿。
2. 普通读者继续看到**旧公开版本**，评论和当前 URL 不受草稿修改影响。
3. 管理员点击“发布更新”，系统校验并原子性切换公开内容。
4. 刷新必要的缓存、搜索及站点地图，记录公开更新时间。

### 6.3 用户注册与评论
1. 用户填写昵称、邮箱、密码，提交注册。
2. 系统发送邮箱验证链接；未验证前不允许评论。
3. 验证成功后登录，进入文章详情并提交评论。
4. 评论经过服务端鉴权、限流和内容安全校验后**立即对外公开**。
5. 用户可以删除自己的评论；管理员可事后隐藏/删除评论或禁用账号。

### 6.4 密码找回
1. 用户提交邮箱，页面返回不泄露账号是否存在的统一提示。
2. 有效账号收到一次性、限时重置链接。
3. 用户设置新密码，链接失效；按安全策略使相关会话失效。

### 6.5 部署与恢复
1. 配置环境变量/密钥、准备宿主机持久化目录。
2. 执行 Docker Compose 部署；应用与数据库健康检查通过。
3. 通过现有反向代理配置域名与 HTTPS；内部服务不直接暴露公网。
4. 备份数据库、媒体目录及必要配置，演练恢复。
5. 新版本发布前执行兼容性检查/备份，再按文档升级且不删除持久化数据。

## 7. 逻辑数据对象（不限定数据库实现）

| 对象 | 核心含义/关系 |
|---|---|
| User | 邮箱、密码哈希、昵称、头像、验证状态、账号状态、角色 |
| AuthSession / EmailToken | 登录会话、邮箱验证及密码重置的一次性令牌或其安全摘要 |
| Article | 文章稳定标识、公开状态、作者、当前 Slug、评论开关及时间字段 |
| ArticleDraft | 未公开的编辑内容和编辑中的发布元数据 |
| ArticlePublished | 当前对外可见的正文和发布元数据快照 |
| Category / Tag | 分类、标签及与文章的关联 |
| ArticleSlugHistory | 文章地址变更的旧 Slug 与重定向映射 |
| Comment | 作者、文章、父评论、回复目标、正文、可见性和时间 |
| MediaAsset | 本地资源路径、格式、尺寸、大小、上传者、资源标识 |
| SiteSetting / NavLink | 网站基础信息、导航、个人栏外链图标及排序 |
| AdminAuditLog | 管理员对高风险对象执行的重要操作日志 |

> 本节只是产品领域对象，不是物理表设计、字段 SQL 或 ORM 方案。物理数据库与迁移方案留待技术设计阶段。

## 8. 非功能性需求

### 8.1 安全与隐私
- 密码只存储安全哈希；数据库、SMTP 凭证和初始化管理员密钥不进入公开代码仓库。
- 验证/重置链接具有一次性、有效期、限流及失败重试处理；防止账号存在性枚举。
- 会话 Cookie 采用 HttpOnly、Secure（HTTPS）、合理 SameSite；涉及状态变更的请求有 CSRF 防护或等效措施。
- 所有评论、Markdown、头像与图片相关输入都经过相应的安全处理；禁止脚本注入、路径遍历、危险文件类型及任意文件执行。
- 后台、编辑草稿、未发布/撤回文章和普通用户资料不得经接口或缓存意外泄漏。
- 登录、注册、评论、邮件发送、图片上传设置限流与日志；避免滥用公开 SMTP 服务。
- 在 UI 中只公开用户昵称、头像等必要信息，默认不公开评论用户邮箱。

### 8.2 可用性与体验
- 适配主流桌面及移动浏览器；重点检查 360px、768px、1280px 等典型视口。
- Markdown 编辑、自动保存、上传与发布操作具有明确的加载、成功和错误状态。
- 不允许已登录用户刷新页面后丢失正常会话，也不允许草稿在重建容器后丢失。
- 浏览文章不要求登录；文章不存在、被撤回或无访问权限时返回恰当状态及界面。
- 公开页面能被搜索引擎正确获取主体文章内容；搜索、列表和评论有分页，避免一次返回全部数据。
- 关注首屏加载、图片体积与缓存策略；可在技术设计时明确测试环境和性能阈值。

### 8.3 可维护性
- 前台、文章、评论、身份认证、媒体、站点配置和管理员操作按业务模块划分。
- 数据结构修改使用可追踪的迁移脚本；迁移前后保持数据兼容与可恢复性。
- 核心业务流程需要自动化测试和必要的端到端验收。
- 详细说明开发、配置、部署、备份、恢复、更新和回滚步骤。

## 9. 部署、交付与版本管理

### 9.1 部署要求
- 支持 Docker Compose 一键启动所需服务；数据库有独立持久化卷或宿主机挂载目录。
- 图片使用**服务器本地持久化目录**，容器重建/版本升级后必须可用。
- 支持 Nginx Proxy Manager 反代与 HTTPS；对公网暴露反向代理入口，内部数据库等端口仅容器网络可达。
- 应用提供健康检查；配置通过环境变量/密钥注入，项目提供脱敏配置示例。
- 数据库、媒体目录和关键配置分别纳入备份；至少完成一次隔离环境恢复验证。

### 9.2 开发交付规范
- 每完成一个开发阶段，提交阶段交付文档：已完成项、测试结果、已知问题、当前进度与下一步计划。
- 接入 GitHub 后，每次正式版本修改按约定提交并推送远程仓库；密钥、用户数据、备份及上传图片不得误提交。
- 网站类项目必须随项目提供 Docker Compose 部署方案、初始化指导和更新说明。
- **当前仅输出 PRD，不初始化仓库、不创建代码、不连接服务器、不部署。**

## 10. 异常与边界处理

| 场景 | 预期行为 |
|---|---|
| 注册邮箱已存在 | 给出安全且可理解的提示，不泄露多余账号信息 |
| 验证链接过期/已使用 | 提示失败，并允许按限流规则重新申请 |
| 忘记密码邮箱不存在 | 对外保持统一提示，防止枚举账号 |
| SMTP 发送失败 | 不误报发送成功；允许稍后重试并记录错误 |
| 上传超限/伪装格式 | 拒绝上传，提示允许的格式/大小 |
| 删除被文章引用的图片 | 阻止或强提示，不应悄悄破坏线上文章 |
| 编辑已发布文章期间断网 | 尽量保留本地编辑状态，恢复后继续保存，不改变公开版本 |
| 草稿与发布版本的元数据不一致 | 以公开快照对访客展示，直到“发布更新” |
| 用户评论时被封禁/文章关闭评论 | 后端拒绝新增评论，并显示合理提示 |
| 删除有子回复的评论 | 采用删除占位等方式维持回复链条 |
| 修改文章 URL | 按策略建立旧链接重定向，避免死链 |
| 管理员撤回/删除文章 | 不再出现在列表、搜索、RSS 和 Sitemap；禁止普通用户访问 |

## 11. 上线验收标准（UAT）

| 编号 | 验收场景 | 通过标准 |
|---|---|---|
| UAT-01 | 浏览与响应式 | PC、平板、手机可浏览首页、文章、分类、标签、归档、搜索和关于页；无明显布局溢出 |
| UAT-02 | 文章发布 | 新建 Markdown 草稿、预览、上传插图、发布后前台正常显示 |
| UAT-03 | 文章版本隔离 | 修改已发布文章并自动保存时，前台仍显示旧版本；点击发布更新后才展示新版本 |
| UAT-04 | 撤回与回收站 | 撤回/删除文章后前台不可见，恢复操作不丢失内容和评论 |
| UAT-05 | 邮箱注册 | 新用户注册收信、链接验证、登录退出均正常，未验证用户不能评论 |
| UAT-06 | 密码找回 | 重置链接一次性有效，过期无法复用，密码更新后可正常登录 |
| UAT-07 | 评论直接公开 | 已验证用户评论/回复提交后立即显示，游客无法发表 |
| UAT-08 | 评论治理 | 本人可删除自己的评论；管理员可隐藏/删除他人评论、禁用账号 |
| UAT-09 | 本地媒体持久化 | 图片上传后可引用；容器重建后图片仍可正常访问，删除保护生效 |
| UAT-10 | SEO 与可见性 | 公开文章可索引；草稿、已撤回文章、后台和个人私有数据不被意外公开 |
| UAT-11 | 后台与设置 | 管理员能管理文章、用户、评论、媒体及基础站点信息，普通用户不可进入后台 |
| UAT-12 | 部署与恢复 | 在全新环境依文档部署成功；数据库和图片可以备份及恢复，版本升级不丢数据 |
| UAT-13 | 基础安全 | 验证/重置限时单次、限流、上传校验、鉴权、XSS/CSRF 防护相关测试通过 |
| UAT-14 | 文档与版本 | 阶段交付文档完整，GitHub 版本记录及部署更新文档可追溯 |
