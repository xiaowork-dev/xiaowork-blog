## 0. 设计目标与决策状态

### 0.1 已由产品所有者明确确认，不得擅自改变

1. 前台采用 **左侧个人资料卡 + 右侧博客文章区**（不是文章左、资料右），整体为**现代简约**风格。
2. 左侧资料栏只放 **头像、昵称、短简介、GitHub/邮箱等少量可配置外链图标**。不放天气、音乐、文章计数、标签云等功能组件。
3. PC 双栏，手机上下单栏；前台的首页和文章详情共享统一外壳。
4. 后台文章编辑采用 **Markdown 源码编辑 + 实时预览**；已发布内容与编辑草稿彻底隔离，管理员必须点击“发布更新”才对外生效。
5. 访客无需登录即可阅读文章；用户通过邮箱+密码注册，验证邮箱后登录并发表评论；评论合法提交后**直接公开**，管理员事后处理；没有审核队列。
6. 文章图片和头像存于本地服务器持久化目录；草稿中的私有图片不向游客公开。
7. V1.0 有首页、文章、分类、标签、归档、搜索、关于页、登录注册、用户中心、管理后台、基础 SEO 和响应式。
8. 首版不做第三方登录、点赞、站内通知、图片评论、复杂统计报表、多人协作、AI 写作等扩展业务。

### 0.2 本文的设计建议（等待视觉稿评审后锁定）

- 品牌色、灰阶、字号与圆角、具体留白；卡片是否有轻微悬停阴影。
- 导航项数量与移动端菜单表现；文章摘要展示行数和卡片封面比例。
- 后台左侧导航宽度、表格密度、弹窗宽度等布局数字。
- 自动保存的操作节奏及提示文案；仅属于 UI 建议，不改动 API 的 revision CAS 契约。

所有示例昵称、文章及数字都是**占位数据**，非博客真实内容。

## 1. 信息架构与页面清单

### 1.1 公开前台（公开访问）

| 页面 | Nuxt 路由建议 | 核心职责 |
|---|---|---|
| 首页 | `/` | 最新公开文章分页、固定的左侧个人栏 |
| 文章详情 | `/posts/:slug` | 标题、元信息、Markdown、目录、图片、评论 |
| 分类总览 | `/categories` | 分类卡片/列表 |
| 分类详情 | `/categories/:slug` | 分类下公开文章列表 |
| 标签总览 | `/tags` | 标签汇总 |
| 标签详情 | `/tags/:slug` | 标签下公开文章列表 |
| 归档 | `/archives` | 按年份、月份整理公开文章 |
| 搜索 | `/search?q=...` | 搜索结果、关键词提示、空状态 |
| 关于 | `/about` | 博主自定义公开内容 |
| 未找到 | 404 | 返回首页、搜索引导 |

### 1.2 认证与个人中心

| 页面 | Nuxt 路由建议 | 关键状态 |
|---|---|---|
| 登录 | `/auth/login` | 正常、密码错误、限流、待验证 |

| 邮箱验证 | `/auth/verify-email?token=...` | 等待确认、成功、过期、已用 |
| 忘记密码 | `/auth/forgot-password` | 统一发信提示，不暴露邮箱是否存在 |
| 重置密码 | `/auth/reset-password?token=...` | 二次确认、新密码成功/失败 |
| 我的资料 | `/account/profile` | 昵称、头像、简介和邮箱状态 |
| 我的评论 | `/account/comments` | 评论记录、删除确认 |
| 账号安全 | `/account/security` | 修改密码、更换邮箱、退出所有设备 |

### 1.3 管理后台（仅管理员）

| 页面 | Nuxt 路由建议 | 核心职责 |
|---|---|---|
| 控制台 | `/admin` | 概览数字、近期内容变更、异常提示 |
| 文章列表 | `/admin/articles` | 按状态/分类检索、操作和回收站 |
| 新建文章 | `/admin/articles/new` | 创建空草稿后进入编辑器 |
| 文章编辑 | `/admin/articles/:id/edit` | Markdown 工作区、草稿保存、发布更新 |
| 分类 | `/admin/categories` | CRUD 与关联影响提醒 |
| 标签 | `/admin/tags` | CRUD 与关联影响提醒 |
| 评论 | `/admin/comments` | 已公开、已隐藏、已删除/墓碑查询；**无待审核** |
| 用户 | `/admin/users` | 账号查询、状态、禁用和解禁 |
| 媒体库 | `/admin/media` | 上传、预览、复用、引用保护 |

**权限 UI 原则：** 匿名访问 `/account/*`、`/admin/*` 时，应按当前身份进行登录引导或无权限提示；前端隐藏按钮不替代 Go API 鉴权。管理员路由 SSR 不缓存私人数据。

## 2. 视觉语言与设计系统（建议初稿）

### 2.1 气质关键词

**现代、简洁、安静、技术感适度、内容优先。** 不大量使用高饱和渐变、玻璃拟态或持续动画。内容页面强调排版，后台强调效率与状态可读。

### 2.2 语义颜色（建议值，评审可调）

| 语义 | 浅色主题 | 深色主题 | 说明 |
|---|---|---|---|
| 页面背景 | `#F7F8FA` | `#0B1018` | 低干扰背景 |
| 卡片 / 弹层 | `#FFFFFF` | `#151C26` | 主要承载面 |
| 主文字 | `#171B22` | `#F3F5F8` | 标题和正文 |
| 次级文字 | `#667085` | `#97A3B6` | 时间、辅助信息 |
| 边框 | `#E5E7EB` | `#273241` | 分区边界 |
| 链接 / 强调 | `#2563EB` | `#60A5FA` | 链接和主按钮 |
| 成功 | `#16803C` | `#4ADE80` | 已保存、已发布 |
| 警告 | `#B45309` | `#FBBF24` | 草稿未保存、风险提示 |
| 错误 | `#B42318` | `#F87171` | 失败、危险操作 |

颜色必须检查实际文字/背景组合的可读性（普通文本目标 WCAG AA 4.5:1；大文本不低于 3:1），不能只以外观接近此表作为验收。

#### 2.2.1 P8-B8 配色升级（当前实现，见 ADR-0011）

布局不变，颜色层次更丰富：主强调色为科技蓝，低饱和的青、橙、紫只用于分类圆点、标签、行内代码等小面积点缀；渐变只出现在细线（卡片悬停顶线、阅读进度条、标题竖条）和资料卡顶部的浅色带。Token 统一定义在 `apps/web/app/assets/css/main.css`。

| Token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bg` | `#F5F7FB` | `#0B1020` | 页面背景 |
| `--card` | `#FFFFFF` | `#121A2A` | 卡片 / 弹层 |
| `--text` | `#141A26` | `#E8EDF6` | 标题和正文 |
| `--muted` | `#5B6678` | `#9AA5B8` | 日期、摘要、辅助信息 |
| `--border` / `--border-strong` | `#E2E7EF` / `#CFD7E3` | `#22304A` / `#31425F` | 分区边界 |
| `--accent`（`--accent-soft`） | `#2A62D5`（`#EEF3FE`） | `#6C9DFF`（`#17264A`） | 链接、主按钮、导航激活、标签 |
| `--teal`（`--teal-soft`） | `#0B766C`（`#E6F6F3`） | `#4FD8C4`（`#102A2C`） | 标签色调 |
| `--amber`（`--amber-soft`） | `#A85A05`（`#FDF3E4`） | `#F5B04A`（`#2C2213`） | 标签色调、代码语言圆点 |
| `--violet`（`--violet-soft`） | `#6A4BD4`（`#F1EDFD`） | `#AB9CFF`（`#211D40`） | 标签色调、行内代码 |
| `--code-bg` | `#F4F6FA` | `#0D1424` | 代码块背景 |
| `--brand-gradient` | `#4F8CFF → #2DD4BF → #F59E0B` | 同左 | 仅用于 2–3 px 细线 |

实测对比度（WCAG 相对亮度公式）：浅色次级文字 5.41–5.81、强调蓝 5.52、标签文字在各自浅底上 4.63–5.12；深色次级文字 7.00、强调蓝 6.55、标签文字 5.60–8.60；主按钮文字 5.52（浅）/ 7.13（深）。全部 ≥ 4.5。

### 2.3 字体、间距和控件

- UI 字体：系统优先中文字体栈（苹方、思源黑体、微软雅黑等）；英文可采用相容的系统无衬线字体。避免依赖必须联网才能加载的唯一字体。
- 阅读正文：PC **16–18 px**、行高 **1.8**；正文舒适最大宽度建议 **720–760 px**。
- UI 文本：13/14/16 px；正文小于 14 px 的地方尽量限于短辅助信息。
- 标题阶梯（建议）：H1 32–36、H2 26–28、H3 22–24 px；在手机端相应缩小。
- 间距体系建议：4/8/12/16/24/32/48 px；卡片圆角 10–14 px；主要控件点击高度至少 40–44 px。
- 分隔优先用细边框、留白；阴影轻量；交互动画 120–200 ms，尊重 `prefers-reduced-motion`。
- 图标使用一致线性风格，图标链接必须有可访问名称、Hover/Focus 状态和 Tooltip。

### 2.4 页面栅格与断点

| 视口 | 布局 | 规则 |
|---|---|---|
| ≥1200 px | PC 两栏 | 页面最大宽约 1200 px；左栏 244–264 px；列距 40–56 px；右栏伸缩 |
| 768–1199 px | 紧凑两栏或单栏 | 保障正文阅读宽度；避免挤压代码块 |
| ≤767 px | 单栏 | 个人资料变顶部简洁卡，顶部导航改菜单，左右安全边距 16–20 px |
| ≤375 px | 小屏检验 | 不横向溢出、长 URL 断行、按钮合理换行 |

**PC 左侧个人栏 Sticky**：相对视口顶部导航留出安全距离；资料内容高度超过视口时允许正常滚动，不将资料卡固定到遮挡其他控件。详情页同样保留布局。移动端资料卡位于主内容之前，信息收紧到头像、昵称、简介和图标。

## 4. 前台核心页面

### 4.1 首页 `/`

- 首屏展示“最新文章”标题与文章列表，不额外做大型宣传横幅或作品展示。
- 每张文章卡：标题（最显著）、首次发布时间、分类、摘要最多 2–3 行、封面（如有）、可选阅读数；无封面时为纯文字卡，不保留大面积空图片区。
- 标题和卡片明确点击区；文章标签如展示则独立可点，防止整卡点击冲突。
- 分页优先标准可访问分页链接（利于 SEO），而非无限瀑布流。
- 加载：Skeleton；空文章：提示“还没有发布文章”；错误：提供重试或返回首页。
- API：`GET /api/v1/site`、`GET /api/v1/articles`。

### 4.2 文章详情 `/posts/:slug`

- 头部：文章标题、摘要（如有）、发布日期与公开更新时间（有意义时）、分类、阅读数。
- 主体：Markdown 正文、标题层级与锚点、代码语言标签与复制、表格横向滚动、图片放大与懒加载、外链安全提示。
- 目录：PC 可在主阅读区旁置独立浮动目录；不能挤压正文；手机折叠显示。
- 底部：标签、上一篇/下一篇、评论区；评论关闭时保留历史评论并显示“本文已关闭评论”。
- 旧 Slug：在服务端输出 301 至 canonical，避免客户端闪烁与重复索引。
- 文章不可见：不对游客展示草稿状态，统一 404。
- API：`GET /api/v1/articles/{slug}`、评论和浏览事件接口。

### 4.3 分类、标签、归档、搜索

- 分类 `/categories`：分类名称、公开文章数量，点击进入详情。无分类时显示空状态。
- 标签 `/tags`：标签列表/紧凑标签块；避免夸张字体权重影响可读性。标签详情复用文章列表组件。
- 归档 `/archives`：按年、月分组，日期-标题列表；可折叠，保持链接可访问性。
- 搜索 `/search`：搜索输入框预填 URL 查询词，提交时同步地址栏；标题关键词高亮须安全转义；结果只包含公开文章。
- 搜索空结果文案：`没有找到与“关键词”相关的文章`，提供清空或返回全部文章入口。
- 中文搜索结果取决于后端能力；不要在 UI 中承诺未实现的语义搜索。
- 以上页面复用统一左侧个人栏，不引入第二套博客导航。

### 4.4 关于页 `/about`

- 左侧沿用资料卡；右侧为后台编辑的公开 Markdown 内容。
- 若内容尚未配置，提供简洁的空白占位，不暴露编辑入口给普通访客。

## 5. 评论系统 UI/UX

### 5.1 入口与权限状态

| 当前状态 | 输入区域表现 |
|---|---|
| 游客 | 展示评论及回复；输入处显示“登录后参与讨论”和登录入口 |
| 已注册但邮箱未验证 | 不开放发送；显示验证邮箱提示和重发入口 |
| 已登录、已验证 | 文本输入框、字数提示、提交按钮 |
| 账号被禁用 | 提示不能评论，不暴露其他账号信息 |
| 文章关闭评论 | 不显示可用编辑框，保留历史评论，显示关闭说明 |

### 5.2 评论列表与回复

- 默认最新在前，可切换最早在前。顶层评论独立分页，根评论之下的回复延迟加载。
- 展示头像、昵称、时间、正文、回复目标；博主显示小型“博主”身份标识。
- 视觉最多 **两级缩进**，真实回复关系使用数据库 parent/root 字段，避免无限缩进。
- 评论只支持纯文本、换行、Emoji 和安全处理的链接；禁止 HTML/图片上传控件。
- 提交成功后立即把服务器返回的可见评论加入列表；**绝不出现“等待审核”状态**。
- 评论失败时保留输入内容，支持重试；429 时给出冷却时间。
- 回复按钮打开输入框，并显示“回复 @昵称”；提交时绑定真实评论 ID。
- 自己的评论允许删除。已有子回复时删除后显示“该评论已删除”，但保留结构。
- 管理员可以在管理界面隐藏/恢复/删除；不配置审核队列页签。

## 6. 登录注册与用户中心

### 6.1 表单视觉

- 与前台风格一致，但可采用居中窄卡（宽约 400–440 px），减少干扰。
- 注册字段：昵称、邮箱、密码、确认密码；明确必要校验与同意提示（实际法律文案另审）。
- 登录字段：邮箱、密码；提供忘记密码、注册入口。
- 密码输入框支持显示/隐藏；错误提示与字段关联，不能只使用红色边框。
- 异常：网络断开、登录失败、限流、邮箱未验证有独立提示；保护邮箱存在性信息。

### 6.2 邮箱验证与找回

- 验证链接的 GET 页面只展示状态与“确认验证”操作；用户点击后调用 `POST /auth/verify-email`，不在 GET 自动消费令牌。
- 重置密码链接 GET 页面显示输入新密码表单，提交才 `POST /auth/reset-password`。
- 已过期/已使用链接给出明确操作选项；允许按限流规则申请新邮件。
- 忘记密码提交后使用统一提示，不泄露账号是否存在。

### 6.3 用户中心

- `/account/profile`：昵称、头像、简介和邮箱验证状态；头像支持上传/预览/失败回退。
- `/account/security`：修改密码、新邮箱验证、退出其他设备；敏感动作需要明确确认和状态反馈。
- `/account/comments`：我的评论列表（原文章标题、发表时间、内容摘要、评论状态），删除自己的评论前二次确认。
- 普通用户无“发表文章”“后台管理”入口；管理员可通过用户菜单进入后台。

## 7. 管理后台设计

### 7.1 框架

- 采用与前台区分的**功能型后台布局**：左侧固定导航（建议 220–240 px），右侧主工作区；顶部有页面标题、当前管理员、快捷返回博客链接。
- 导航：控制台、文章管理、分类、标签、评论、用户、媒体库、网站设置、关于页。
- 后台建议强调数据密度与明确反馈，避免套用前台个人栏造成工作效率下降。
- 手机端：侧栏收起为抽屉，表格转为横向滚动/信息卡，主要表单单列。

### 7.2 控制台 `/admin`

- 统计卡：文章总数、公开文章数、用户总数、评论总数；近期文章变更和异常/安全提示。
- 不展示“待审核评论”数字，因为 V1.0 评论直接公开。
- 不做复杂访问统计图表。

### 7.3 文章列表 `/admin/articles`

- 顶部“新建文章”主按钮；筛选项包含文章标题、状态（草稿/已发布/已撤回/回收站）、分类。
- 列表展示标题、状态、最后草稿保存时间、公开更新时间、是否有未发布修改。
- 行内快捷操作：编辑、预览、发布/发布更新、撤回、移动回收站、恢复（按状态不同呈现）。
- 危险操作必须确认，并明确“删除不等于清理图片/评论”。

### 7.4 Markdown 文章编辑器（核心）

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ ← 文章管理   标题                                  已保存  预览  发布更新 │
├───────────────────────────────┬────────────────────────────────────────────┤
│ Markdown 原文                  │ 实时预览                                   │
│                               │                                            │
│ # 标题                        │ 标题                                       │
│ 正文与代码                    │ 渲染后的段落、代码与图片                   │
│                               │                                            │
├───────────────────────────────┴────────────────────────────────────────────┤
│ 编辑 / 分栏 / 预览  ·  分类、标签、封面、Slug、SEO、评论开关可在设置抽屉中改 │
└────────────────────────────────────────────────────────────────────────────┘
```

**正式交互规范：**

1. 新建文章先请求创建空草稿，获得文章 ID 与 `revision`；后续只编辑这一份草稿。
2. 页面标题行醒目；编辑区切换 **源码/分栏/预览**，默认分栏；支持导入和导出 `.md`。
3. 文章元信息（摘要、分类、标签、封面、Slug、SEO、评论开关）位于侧边设置抽屉，避免正文工具栏过载。
4. 草稿内容和元信息统一执行自动保存；建议短暂停顿后保存，显示 `正在保存… / 已保存于 19:30 / 保存失败 / 未保存修改`。
5. “发布”或“发布更新”必须是显式动作；按钮不会因为自动保存而自动公开内容。
6. 显示已发布状态和“存在未发布修改”的清晰区分；用户可打开公开文章进行对比。
7. 保存请求携带 `expected_revision`；若 409 冲突，**保留本地未保存内容**，弹出差异处理提示，不自动覆盖服务器草稿。
8. 发布前确认弹窗列出将更新的标题、分类、封面、Slug、评论开关等；发布成功给出“查看公开文章”入口。
9. 429、网络中断、上传失败等情况下保留输入和明确错误原因；编辑器不能因路由跳转无声丢失未保存数据。
10. 草稿图片可仅由已授权管理端预览；公开页永远不直接读取未发布草稿媒体 URL。

### 7.5 评论管理 `/admin/comments`

- 筛选：文章、用户、时间、可见状态（公开/已隐藏/已删除）。
- 操作：隐藏、恢复隐藏、删除、跳转对应文章；关联用户可跳转用户管理。
- 删除/隐藏二次确认，显示处理结果；**不设“待审核”“通过审核”等按钮**。

### 7.6 用户管理 `/admin/users`

- 搜索邮箱/昵称；表格展示昵称、邮箱验证状态、账号启用状态、注册时间。
- 用户详情可查看其评论摘要，允许禁用/解禁普通用户。
- 禁用操作需确认会影响当前会话；不得开放“将普通用户提升为 ADMIN”的 UI。

### 7.7 媒体库 `/admin/media`

- 列表可按文件名、上传时间筛选；图片网格 + 可访问详情列表。
- 单个媒体显示尺寸、大小、上传时间、引用状态、复制使用链接按钮。
- 删除被引用的媒体时禁止操作并提示“仍被文章/头像等引用”，不可默默删除。
- 上传可拖拽/选择/粘贴（编辑器中），状态包括校验中、上传中、成功、失败；支持重试。
- 草稿图片受访问权限保护，普通游客不能因为猜到 `/media/{id}/file` 地址就获取。

### 7.8 站点设置与关于页

- 站点设置：站点标题、Logo/Favicon、简介、左侧个人资料、外链图标/地址/排序/显隐、导航项和基础 SEO。
- 外链在后台可排序，配置时校验协议与 URL；不将外链预览和真实点击区混淆。
- 关于页属于例外：按 API 基线，保存即改变公开页面；UI 必须明显提示“保存后立即生效”，不要伪装为文章草稿-发布两阶段。
- SMTP 密码等部署密钥不应出现在普通站点设置表单里。

## 8. 通用交互状态与错误策略

| 场景 | 用户可见反馈 | 禁止行为 |
|---|---|---|
| 页面初次加载 | 轻量骨架、稳定布局 | 无限旋转不解释 |
| 列表无数据 | 明确空状态及下一步入口 | 空白屏 |
| 401 未登录/过期 | 登录引导，必要时返回原目标页 | 默默清空编辑内容 |
| 403 权限不足 | 无权限说明 | 泄露后台数据 |
| 403 邮箱未验证 | 验证引导 | 误显示等待审核 |
| 404 不存在/未公开 | 统一 404，不泄露草稿是否存在 | 显示未公开文章标题 |
| 409 草稿修订冲突 | 比较/复制/重新加载，保留本地原文 | 静默覆盖 |
| 409 媒体被引用 | 说明不可删除及引用原因 | 删除成功假提示 |
| 413/415 上传问题 | 给出文件大小/格式说明 | 清空上传队列 |
| 422 字段校验 | 具体字段错误与定位 | 只弹通用错误 |
| 429 限流 | 显示可重试时间（若 API 提供） | 持续自动重试 |
| 503 邮件故障 | 诚实提示发送失败/稍后重试 | 误称邮件已发送 |
| 网络断开 | 保留编辑内容，显示离线/保存失败 | 触发隐式发布 |

Toast 用于短反馈；需要决策的冲突或危险操作用对话框；复杂表单的校验使用字段旁提示。所有成功与错误状态不只靠颜色传达。

## 9. 状态流转与 API 对齐

| UI 操作 | Go API 契约 | UI 必要细节 |
|---|---|---|
| 浏览文章列表 | `GET /api/v1/articles` | SSR 可索引，分页 |
| 浏览详情 | `GET /api/v1/articles/{slug}` | 仅公开版本，旧 Slug 301 |
| 搜索 | `GET /api/v1/search/articles` | URL 参数与分页同步 |
| 登录 | `POST /api/v1/auth/login` | Session Cookie，CSRF |
| 获取当前用户 | `GET /api/v1/auth/me` | 顶部用户态，无缓存泄露 |
| 验证邮箱 | `POST /api/v1/auth/verify-email` | 人工确认后 POST |
| 新建文章 | `POST /api/v1/admin/articles` | 返回草稿 ID + Revision |
| 保存草稿 | `PUT /api/v1/admin/articles/{id}/draft` | expected_revision；409 保留内容 |
| 发布更新 | `POST /api/v1/admin/articles/{id}/publish` | 显式确认；可处理重复点击 |
| 发表评论 | `POST /api/v1/articles/{id}/comments` | 成功后直接公开 |
| 回复评论 | `POST /api/v1/comments/{id}/replies` | 真实父级绑定 |
| 删除我的评论 | `DELETE /api/v1/comments/{id}` | 删除占位处理 |
| 媒体上传 | `POST /api/v1/admin/media` | 受限类型；上传状态 |
| 私有媒体预览 | `GET /media/{id}/file` | 鉴权、不可缓存泄漏 |
| 关于页管理 | `PUT /api/v1/admin/pages/about` | 保存后立即公开 |

**对 API 草案的注意事项：** API 是设计稿，实施前需共同冻结数据 DTO 和字段级校验；UI 不应私自新增接口或猜测后端响应。Nuxt SSR 中涉及 Cookie 的后端请求需明确安全的上下文传递，不能把私人 Session 信息写入公共 payload 或 SSR 缓存。

## 10. 无障碍、SEO 与性能设计验收

- 关键操作可用键盘完成；导航与弹窗具备焦点管理，输入框关联 Label，屏幕阅读器可以识别图标链接。
- 明暗主题需要可读对比度；图标不可作为唯一状态信号；成功、失败、警告须有文案。
- 文章标题 H1 唯一且语义层级合理，正文来源 Markdown 渲染后语义正确；目录仅锚到有效标题。
- 公开内容使用 Nuxt SSR 正确产出 Title、Description、canonical 与 OG；后台、私有用户页、草稿不进入公开索引。
- 公开图片可延迟加载，首屏重要内容不应强制等待全部图片；文章代码块及长网址不得造成页面横向溢出。
- 响应式验收至少覆盖 360、375、768、1024、1280、1440 px；标准浏览器缩放 200% 下仍可使用。
- 主题偏好保存时避免首屏亮暗闪烁；尊重系统减弱动效偏好。
- 邮箱重置、后台和个人页避免错误缓存；未发布媒体不能通过匿名获取。
