## 4. 许可证建议

推荐 **MIT License**：

- 依赖全部是宽松许可，没有冲突；
- 对自托管用户和二次开发者最简单；
- 与 Nuxt、Vue、Go 生态的主流做法一致。

其他可选方案：

- **Apache-2.0**：包含明确的专利授权与贡献条款，但文本更长；
- **AGPL-3.0**：要求修改后提供网络服务的人也公开源码。如果希望防止他人闭源托管，可以考虑；但这会降低采用率，也限制商业二次开发。

## 5. 需要项目负责人确认的事项

1. **版权主体**：`LICENSE` 中的 “Copyright (c) 2026 ___” 写个人姓名、GitHub 用户名 `xiaowork-dev`，还是组织名称。
2. **许可协议**：是否采用 MIT（或其他协议）。确认后再加入 `LICENSE`，并在 README 中说明。在此之前，仓库虽然公开，但在法律上仍然保留所有权利，他人无权使用或修改。
3. **`visual_overview.png`**：是否有权公开分发；不能确认时是否删除。
4. **`docs/reference/`**：是否同意把全部需求与设计文档作为开源仓库的一部分公开（目前已经公开）。
5. **贡献政策**：许可确定后是否接受外部 PR；是否要求 DCO（`Signed-off-by`）。
6. **GitHub 仓库设置**（`docs/RELEASING.md` §3）：
   - 标签保护规则集；
   - Release immutability；
   - 私密漏洞报告；
   - `main` 分支保护。
