## 1. 完成内容

### 1.1 版本管理与统一入口

| 文件 | 内容 |
|---|---|
| `deploy/manage.sh`（新增） | 服务器所有者的统一入口：`install`、`status`、`check`、`update`、`rollback`、`backup`、`restore`、`precheck`、`admin`，不带参数时显示菜单。<br>- **版本来源**：只认 GitHub Releases 中标签为 `vX.Y.Z[-后缀]`、非草稿的版本。默认只推荐正式版；预发布版需要 `--pre`；`main` 等未发布代码需要 `--allow-unreleased`。<br>- **更新前计划**：当前 / 目标版本与提交、发布日期、方向（升级 / 降级）、数据库迁移变化、更新说明。<br>- **确认**：终端中输入目标版本号；非终端必须加 `--yes`。<br>- **失败处理**：GitHub 不可达、速率限制、404、5xx、非 JSON、版本无效时，在任何改动前报错退出。<br>- **标签不可变**：移动过的标签被拒绝，分两层检查（git fetch 拒绝覆盖本地标签，以及服务器记录的标签与提交的对应关系）。<br>- **实际执行**：更新调用 `update.sh --ref`，回滚调用 `rollback.sh`，不重复实现 |
| `deploy/update.sh` | 不再默认 `origin/main`，必须 `--ref` 或 `--no-fetch`。分支名解析为 `origin/<分支>` 并警告为开发代码。fetch 失败（含标签被移动）和版本不存在时给出明确错误，网站不受影响 |
| `deploy/lib.sh` | - 在 `state/history` 中记录部署的 ref；<br>- 在 `state/tags` 中固定“标签 → 提交”；<br>- 新增 `release_tags_at`、`pinned_tag_ok`、`cidr_overlap`、`subnet_conflicts` |
| `deploy/install.sh` | - 首次运行时在终端中引导填写：域名、数据目录、NPM 网络（列出现有自定义网络与成员）、内部网段（推荐一个不冲突的网段）、SMTP（密码不回显）；<br>- 写入 `.env` 时值加单引号；<br>- 安装前检查网段冲突（冲突则拒绝）和 443 是否有程序监听（没有则警告）；<br>- 非终端时保持原行为 |
| `deploy/env.production.example` | 说明 dotenv 的引号规则 |
| `deploy/test/drill.sh` | 新增模拟 GitHub Releases API（可切换 403 / 500 / 非 JSON / 停止），以及 `release`、`move-tag`、`scenario unreleased` |
| `.github/workflows/ci.yml` | `deploy` 作业新增：<br>- `manage.sh status`；<br>- `manage.sh check`（真实 API，使用作业令牌）；<br>- `update.sh` 没有目标时必须拒绝；<br>- `manage.sh update` 在没有发布版本时必须拒绝。<br>同时修复两处原本无效的断言（`! cmd` 在 `bash -e` 下不会让步骤失败）：第二个管理员被拒绝、预检输出不含密钥 |
