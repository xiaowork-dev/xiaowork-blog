## 7. 已知风险和未完成事项

- **推送标签触发的 CI #31 失败（`deploy` 作业第 10 步），属于 CI 环境中的误报**。原因已通过日志与本地复现确认：
  1. 由标签触发时，`actions/checkout` 用 `git fetch --depth=1 origin +<SHA>:refs/tags/v1.0.0-rc.1` 拉取代码，本地标签成为直接指向提交的**轻量标签**；
  2. 远端是**带注释的标签**（对象 `7deba124`，最终同样指向 `7660028`）；
  3. `manage.sh check` 运行 `git fetch --tags` 时，git 拒绝覆盖本地标签（would clobber），`manage.sh` 把它报告为“远端发布标签被移动”。

  其他影响：

  - **用户不受影响**：本地复现中，普通 `git clone` 得到带注释的标签，`git fetch --tags` 正常；
  - 同一提交在 `main` 上的 CI（#29）以及本阶段的文档提交（#32）都通过；#31 中安装、HTTPS、认证 e2e（23/23）等步骤都通过；
  - **不足之处**：`manage.sh` 没有区分“同一提交的不同标签对象”和“真正被移动的标签”，CI 的 `deploy` 作业也没有正确拉取标签。修复需要修改代码，而 `v1.0.0-rc.1` 已经不可变，所以**本阶段没有修改**，待项目负责人决定（见 §9）；
  - 如果按原计划在同一提交 `7660028` 上发布 `v1.0.0`，推送该标签触发的 CI 也会出现同样的失败。
- `main` 分支保护尚未设置（不影响发布标签，但建议开启，并要求 CI 通过）。
- 标签保护没有经过破坏性验证（见 §4）。
- 预发布版尚未在真实 VPS 上安装验收（由项目负责人自行执行）。
- 标签所在提交中 `CHANGELOG.md` 的 rc.1 标题仍写着“等待确认后创建”。正式版 `v1.0.0` 将发布在同一提交上，因此该提交中的这句话会一直保留；以 Release 页面和最新 `main` 中的 CHANGELOG 为准。
