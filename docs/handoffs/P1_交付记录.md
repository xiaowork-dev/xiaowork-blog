### 2.2 关键约束（摘要，完整见迁移文件与 ADR-0001）

- **邮箱唯一**：`UNIQUE(email_normalized)` + 规范化形式 CHECK（小写、去首尾空白）。
- **草稿/公开隔离**：一文章一草稿（PK）、至多一公开快照（PK）；草稿标签/媒体 FK → `article_drafts`，公开标签/媒体 FK → `article_publications`；公开快照 `slug` 复合 FK → `article_slugs(slug, article_id)`。
- **Slug**：`article_slugs.slug` PK 全站唯一且永不复用；部分唯一索引保证每文章最多一个当前 Slug。
- **评论**：`(article_id,parent_id)` / `(article_id,root_id)` 复合 FK 防跨文章；父/根成对、禁止自回复、墓碑清空正文、隐藏需时间戳、正文 ≤2000。
- **媒体**：MIME 白名单、存储键防目录穿越、尺寸/大小为正、`DELETED` ⇔ `deleted_at`；所有引用 FK 均为 NO ACTION，阻止删除被引用文件。
- **令牌/会话**：只存 32 字节摘要；过期时间晚于创建；CHANGE_EMAIL 必须带目标邮箱。
- **站点**：单例 `id=1`；外链仅 https/mailto；站内导航禁止 `//`；关于页仅 `about`；审计 `details` 必须是 JSON 对象。
- **索引**：按 DD §9 建立（公开列表、评论分页/回复、按作者、反向引用检查、后台排序、审计查询等）。

2. **评论长度上限 2000 写入 CHECK**：取 API 建议默认值；若运营调整需新迁移（ADR-0001 #11）。
3. **Slug 字符集未冻结**：数据库只做最小校验，API 阶段须确定是否允许中文/大写。
4. **迁移账号与运行账号相同**：最小权限分离留待 P8。
5. **中文搜索质量**未验收（仅 trigram 索引就绪），P5 用真实样本测试。
6. `/health/ready` 仍返回 `"stage":"P0"`，未检查迁移版本；不影响功能，后续 API 基础设施阶段可调整。
