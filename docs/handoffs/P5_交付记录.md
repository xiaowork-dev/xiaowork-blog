### 2.1 Go API（`internal/article/discovery.go`、`internal/site`、`db/queries/public.sql`）

| 接口 | 要点 |
|---|---|
| `GET /articles` | 默认每页 10 条，最大 100 条；可按分类、标签筛选，`sort=latest` 或 `oldest`；只返回已公开的文章快照；标签批量查询；`public, no-cache` |
| `GET /categories`、`GET /categories/{slug}/articles` | 只列出启用中的分类，文章数只统计已公开的文章；详情接口在 `meta.category` 中带回分类信息；Slug 不存在返回 404 |
| `GET /tags`、`GET /tags/{slug}/articles` | 规则同上 |
| `GET /archives?year=` | 按站点时区（Asia/Shanghai）的年、月分组；`meta.years` 给出每年篇数；最多返回 2000 篇 |
| `GET /search/articles` | 多个关键词需全部命中（AND）的 ILIKE 子串匹配，`%` 和 `_` 按字面处理；排序依次为标题命中、摘要命中、时间倒序；关键词为空或超长返回 422；每 IP 60 次/分钟 |
| `POST /articles/{id}/views` | 需要 CSRF；同一浏览器上下文 30 分钟内对同一篇只计一次；机器人不计数；每 IP 120 次 / 10 分钟；只接受已公开的文章；只存 HMAC 摘要 |
| `GET /site`、`GET /pages/about` | 只返回公开字段；关于页尚未编写时返回 404 |

## 5. 已知问题与风险

- **搜索**是子串匹配，不支持同义词、拼写纠错或相关度打分。少于 3 个字符的词无法利用 trigram 索引，会退化为顺序扫描，个人博客的数据量下影响很小。数据量明显增大后，需要用 `EXPLAIN` 评估是否改用专门的检索方案。
- **浏览量**是近似值，规则见 ADR-0005 #7。上线前必须正确配置 `TRUSTED_PROXY_CIDRS`，否则所有读者会共用反向代理的 IP 限额。
- **站点设置**（个人栏、外链、导航、关于页、默认 SEO）目前只能读取，编辑界面在 P7。在此之前，左栏显示迁移写入的默认值：XiaoWork、无简介、无头像。
- **文章阅读宽度**：在 1200 px 容器中同时放下个人栏和目录时，正文约 580 px（17 px 字号，每行约 34 个汉字），比 UI/UX 建议的 720–760 px 窄，但对中文阅读仍较舒适；窄屏时目录折叠，正文会变宽。
- sitemap 和 RSS 每次请求都实时查询（不缓存），文章不超过 5000 篇时没有问题。
- 前台页面的 HTML 会在顶栏显示登录用户的昵称，属于个性化内容，不应被共享缓存缓存。当前没有设置整页缓存；P8 配置 NPM 时需要保持“不缓存 HTML”。
- P2/P3 的遗留项仍然存在：上线前需要配置 `TRUSTED_PROXY_CIDRS`；P3 不剥离原图 EXIF。
