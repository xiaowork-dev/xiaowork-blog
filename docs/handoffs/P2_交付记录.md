## 2. 完成模块

### 2.1 Go API 基础设施（`internal/platform/httpx`、`internal/config`）

- **统一响应**：成功 `{data}`，失败 `{error:{code,message,details}, request_id}`；错误码按 API-DD §3.3（`INVALID_REQUEST`、`VALIDATION_FAILED`+`details.fields`、`AUTH_REQUIRED`、`SESSION_EXPIRED`、`INVALID_CREDENTIALS`、`FORBIDDEN`、`EMAIL_NOT_VERIFIED`、`ACCOUNT_DISABLED`、`CSRF_INVALID`、`NOT_FOUND`、`EMAIL_ALREADY_USED`、`TOKEN_INVALID_OR_EXPIRED`、`PAYLOAD_TOO_LARGE`、`UNSUPPORTED_MEDIA_TYPE`、`RATE_LIMITED`+`Retry-After`、`INTERNAL_ERROR`、`SERVICE_UNAVAILABLE`、`MAIL_UNAVAILABLE`）。数据库不可达映射为 503，其他未知错误为 500，内部错误文本只进日志。
- **Request ID 与安全日志**：接受合法的 `X-Request-Id`，否则生成 `req_…`；JSON 结构化日志只记录方法、路径（不含查询串）、状态、耗时、request_id，从不记录 Cookie、请求体、令牌、密码；panic 转 500 并只在日志中保留堆栈。
- **安全头与输入**：`nosniff`、`no-referrer`、`X-Frame-Options: DENY`、CSP；API 默认 `Cache-Control: private, no-store`；JSON 严格解码（Content-Type、64 KiB 上限、拒绝未知字段与多对象）。
- **客户端 IP**：仅信任 `TRUSTED_PROXY_CIDRS` 中的代理，`X-Forwarded-For` 自右向左解析。
- **配置校验**：`DATABASE_URL`、`PUBLIC_BASE_URL`（非 localhost 必须 https）、`APP_SECRET_KEY`（≥32 字节，非本地拒绝示例值）、TTL 范围、`SMTP_*`（非本地必须 TLS），支持 `*_FILE` 密钥文件；全部问题一次性报告，只报变量名不回显值；`Config.String()` 不含任何秘密。

### 2.2 认证功能（`internal/auth`，API-DD §4.2）

| 接口 | 权限 | 要点 |
|---|---|---|
| `GET /auth/csrf` | P | 签发绑定匿名/会话上下文的 HMAC 令牌，必要时设置匿名 Cookie |
| `POST /auth/register` | T | 昵称 1–40、ASCII 邮箱（大小写不敏感唯一）、密码 12–128；总是创建 USER；事务内建用户+资料+验证令牌；同步发信，失败返回 201 + `email_delivery:"unavailable"`；重复邮箱 409 |
| `POST /auth/resend-verification` | T | 统一 202；作废旧验证令牌后异步发送；IP 10/时、同邮箱 1/分 5/日 |
| `POST /auth/verify-email` | T | 一次性消费（条件 UPDATE），校验目标邮箱仍匹配；重复/过期 422 |
| `POST /auth/login` | T | Argon2id 校验；未知邮箱做等价哈希运算；IP 10/10 分，同邮箱失败 5/10 分；未验证 403、禁用 403；登录轮换旧会话 |
| `POST /auth/logout`、`/logout-all` | S | 撤销当前/全部会话并清除 Cookie |
| `GET /auth/me` | S | 本人邮箱、昵称、头像、角色、验证与账号状态 |
| `POST /auth/forgot-password` | T | 统一 202，不暴露账号存在性；异步发送 30 分钟重置链接 |
| `POST /auth/reset-password` | T | 事务内：消费令牌、改密码、撤销全部会话与其他重置令牌 |
| `POST /me/change-password` | S | 校验当前密码；撤销全部会话（要求重新登录） |
| `POST /me/change-email/request` | S | 新邮箱已占用 409；向新邮箱发送确认链接；发送失败作废令牌并返回 503 |
| `POST /me/change-email/confirm` | S | 必须是同一账号的有效会话；唯一键二次裁决；撤销其他设备会话 |

- **权限中间件**：`Authenticate`（每次请求实时校验会话过期/撤销/账号状态）、`RequireUser`(S)、`RequireVerified`(U，供 P6 评论使用)、`RequireAdmin`(A)；`/api/v1/admin/*` 统一先过管理员守卫。
- **CSRF**：所有写请求校验 `X-CSRF-Token` 与 `Origin`（或 `Sec-Fetch-Site: same-origin`）。
- **限流**：持久化于 `auth_rate_windows`，主体为 HMAC 摘要；后台每小时清理过期限流窗口、过期 7 天以上的令牌与会话。
- **首个管理员**：`blog-admin create-admin -email -nickname`，密码读 stdin，advisory 锁 + “已有 ADMIN 即拒绝”，管理员邮箱直接视为已验证；无任何 HTTP 入口。

### 2.3 邮件系统（`internal/mail`）

- 可配置 SMTP（`none` 仅限本地 / `starttls` / `tls`，TLS ≥ 1.2，可选 PLAIN 认证），每封邮件独立连接并有硬超时；拒绝头部换行注入；UTF-8 quoted-printable 纯文本。
- 本地与测试：Compose 新增 Mailpit `axllent/mailpit:v1.32.0`（仅 `127.0.0.1:8025`）；Go 测试使用内存 `Recorder`，并对 Mailpit 做真实 SMTP 投递测试。仓库中没有任何真实 SMTP 凭据。
- 生产：`SMTP_*` 环境变量或 `SMTP_PASSWORD_FILE`，可直接接入未来的自有域名邮箱。

### 2.4 前端（Nuxt）

- `server/routes/api/v1/[...path].ts`：同源代理到 Go API（转发 Cookie/Origin/CSRF，追加 `X-Forwarded-For`）；生产由 NPM 直接路由，契约一致。
- `useApi`（CSRF 获取、登录/退出后轮换、`CSRF_INVALID` 自动重试一次、统一错误含网络断开与 `Retry-After`）、`useAuth`（SSR 期间转发 Cookie 获取当前用户）、`safeRedirect`（禁止开放重定向）。
- 页面：`/auth/login`、`/auth/register`、`/auth/verify`（+ `/auth/verify-email` 别名）、`/auth/forgot-password`、`/auth/reset-password`、`/auth/confirm-email`；顶部栏显示登录/注册或昵称/退出。
- 交互：GET 链接页只展示状态，点击按钮才 POST 消费令牌；令牌读取后立即从地址栏移除；`/auth/**` 响应 `private, no-store` 与 `Referrer-Policy: no-referrer`；字段错误通过 `aria-describedby` 关联；密码显示/隐藏；成功、警告、错误不只靠颜色（含文字与图标）；亮/暗色令牌按 UI/UX §2.2；移动端单栏。

## 5. 已知问题与风险

1. **`TRUSTED_PROXY_CIDRS` 本地默认值 `172.16.0.0/12` 含 Docker 网关**，本机可伪造 `X-Forwarded-For`（仅限能访问 127.0.0.1 端口的本机）。P8 生产部署必须收紧为 NPM 所在网络。
2. **注册限流 3 次/小时/IP**：同一 NAT 出口的多名真实用户可能受影响；阈值按 API-DD“建议默认”实施，上线后按真实流量调整。
3. **邮箱仅支持 ASCII 地址**（ADR-0002 #3），国际化域名需另行评审。
4. 本机 Windows 安全软件拦截 `go test` 自动执行刚生成的部分测试程序，Docker Desktop 端口映射下 SMTP 欢迎语收不到；均为本机环境问题，已用替代方式完成测试，CI 不受影响。
5. 更换邮箱的发起表单、修改密码表单在用户中心（`/account/security`）中，按计划随后续阶段实现；本阶段提供 API 与确认页。
6. 未实现“修改邮箱时通知旧邮箱”的提醒邮件（设计未要求，建议后续考虑）。
7. 生产环境的 HTTPS、`__Host-` Cookie 与 NPM 反代路径须在 P8 实际验证。
