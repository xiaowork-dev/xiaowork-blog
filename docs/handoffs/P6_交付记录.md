## 2. 完成内容

### 2.1 评论 API（`apps/api/internal/comment`、`db/queries/comments_api.sql`）

| 接口 | 权限 | 要点 |
|---|---|---|
| `GET /articles/{article_id}/comments` | P | 只对根评论分页（默认 20 条，最大 50 条），支持最新 / 最早排序。每条根评论附带 2 条回复预览和 `reply_count`，`meta` 中带 `comment_count` 和 `comments_enabled`。文章未公开时返回 404 |
| `GET /comments/{root_id}/replies` | P | 按时间升序分页返回整楼回复；根评论不存在或文章未公开时返回 404 |
| `POST /articles/{article_id}/comments` | U | 正文清洗后长度须为 1–2000 字。限流为每分钟 5 次、每小时 20 次；10 分钟内重复发表相同内容返回 409。事务内对文章和公开快照加 `FOR SHARE` 锁，评论直接写入 VISIBLE |
| `POST /comments/{comment_id}/replies` | U | 文章和根评论都由父评论推出；父评论被隐藏或删除时返回 409 `COMMENT_NOT_REPLYABLE`；评论已关闭时返回 422 `COMMENT_CLOSED` |
| `DELETE /comments/{comment_id}` | S | 只能删除自己的评论，否则返回 403。状态改为 DELETED_AUTHOR 并清空正文，回复保留；重复删除仍返回 204 |
| `GET /me/comments` | S | 返回状态、自己的正文（包括被隐藏的）。文章仍公开时附带标题和链接，否则只返回 `available:false` |
| `GET /admin/comments` | A | 支持按文章、作者、状态（包括“已删除”合并项）、时间范围和关键词筛选；包含作者邮箱和文章状态 |
| `POST /admin/comments/{id}/hide`、`/unhide` | A | 返回 200，重复操作幂等；对已删除的评论返回 409；写入审计日志（不含正文） |
| `DELETE /admin/comments/{id}` | A | 状态改为 DELETED_ADMIN，不可恢复，回复保留；返回 204，写入审计日志 |

公开响应中**只有 VISIBLE 的评论带正文和作者**。隐藏或删除的评论只在仍有直接回复时作为占位出现，没有回复时不出现。任何公开响应都不含邮箱、会话或令牌。健康检查的 stage 改为 `P6`。

### 2.2 账号（`apps/api/internal/auth/profile.go`、`db/queries/account.sql`）

- **`PATCH /me/profile`**：

## 5. 已知问题与风险

- **限流是固定一分钟窗口**（沿用 P2）：请求跨越窗口边界时，最多可短时间通过两个窗口的配额（例如连续 10 条评论）。如需严格的滑动窗口，需要单独设计。
- 评论区在浏览器端加载，SSR 中不包含评论，评论内容不会被搜索引擎收录（按设计如此）。
- 正常流程中，未验证邮箱的账号无法登录，因此“已登录但未验证”的界面分支只在异常情况下出现，已实现但很少触发。
- **禁用账号、用户管理、控制台统计属于 P7**。评论接口已能拒绝被禁用的账号，后台的“作者已禁用”标记也已显示。
- 修改密码会让所有设备退出，包括当前设备（P2 的设计），用户需要重新登录。
- 评论没有编辑功能（PRD 首版不做）。删除自己的评论不可恢复。
- P2/P3 遗留项仍然存在：上线前需要配置 `TRUSTED_PROXY_CIDRS`；P3 不剥离原图 EXIF；P5 的文章阅读宽度约 580 px。
