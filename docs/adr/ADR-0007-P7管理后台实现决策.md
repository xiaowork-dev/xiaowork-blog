# ADR-0007 — P7 管理后台：控制台、用户、站点设置与关于页

- 日期：2026-10-24
- 状态：已采纳（P7）
- 依据：PRD ADMIN-01~08、§4.2；API-DD §4.3（`/admin/overview`）、§4.4（`/admin/users*`、`/admin/site*`、`/admin/pages/about`）、§5.8、§7；DD §8.1~§8.5；UI/UX §7.1~§7.8；实施计划 P7

**没有数据库迁移（仍为版本 7）**：P7 需要的字段在 P1 建的 24 张表中都已具备。所有接口都是 API-DD 已列出的；新增错误码与可选字段如下。

| # | 决定 | 依据 / 理由 |
|---|---|---|
| 1 | **控制台** `GET /admin/overview` 实时查询以下数据：<br>- 文章：总数（不含回收站）、已发布、草稿、已撤回、回收站、有未发布修改；<br>- 用户：总数、未验证、已禁用、近 7 天新增；<br>- 评论：公开、已隐藏、近 7 天新增；<br>- 可用媒体数。<br>另返回最近 6 篇更新的文章和最近 10 条审计记录。<br>`notices` 只来自真实状态：存在没删完的图片（PENDING_DELETE）、只有一个管理员。<br>**不做图表，也不出现任何“待审核”数字** | PRD ADMIN-01；UI/UX §7.2 |
| 2 | **用户管理**：<br>- `GET /admin/users` 支持 `q`（昵称或邮箱）、`status`、`verified`、`role` 筛选并分页；<br>- `GET /admin/users/{id}` 返回资料、评论统计、有效会话数、最近 10 条评论，以及 `can_disable` / `can_enable`；<br>- `POST /admin/users/{id}/disable`、`/enable` **只作用于普通用户（USER）**；对管理员返回 409 **`ADMIN_PROTECTED`**，禁用自己返回 409 **`CANNOT_DISABLE_SELF`**。<br>因为后台既不能禁用任何管理员，也没有修改角色的接口，所以“最后一个管理员被禁用”不可能发生 | API-DD §5.8“禁止直接禁用自身及最后一个 ADMIN，默认只操作普通用户”；UI/UX §7.6“不得开放提升为 ADMIN 的 UI” |
| 3 | 禁用账号时，在**同一事务内**撤销该账号全部会话和所有未使用的一次性令牌（验证、重置、换邮箱）。<br>效果：已登录的设备立即失效；无法登录（P2 返回 403 `ACCOUNT_DISABLED`）、评论或找回密码。<br>已有评论保留，可在评论管理中处理。恢复账号后用户需要重新登录。<br>禁用和恢复都写入审计日志 | API-DD §6.3、§5.6 |
| 4 | **站点设置** `GET/PATCH /admin/site`：<br>- 可修改的字段严格限于 API-DD §5.8 所列：站名、描述、个人栏昵称和简介、头像、Logo、Favicon、公开联系邮箱、默认 SEO；<br>- PATCH 是部分更新：未传的字段保持不变，null 表示清空；传入任何其他字段（如 `smtp_password`）返回 400；<br>- 文本去除首尾空白，并拒绝控制字符和不可见格式字符；<br>- 图片沿用 P3 的规则：必须为 READY 且不能是头像，校验时加 `FOR SHARE` 锁；被站点设置引用的图片自动公开，且受删除保护（P3 已统计 `site_settings` 引用）；<br>- **部署密钥（SMTP、数据库、会话密钥）只存在环境变量中，后台既不读取也不写入** | DD §8.1；PRD ADMIN-07 |
| 5 | **外链与导航**：<br>- `PUT /admin/site/social-links` 与 `/navigation-links`，请求体为 `{"links":[…]}`，**整表替换**，数组顺序即 `sort_order`；带上已有 `id` 可以保持链接 id 不变；<br>- 个人栏外链：图标只能取 `github`、`mail`、`rss`、`link`（前台都有对应图标）；地址只接受 **`https://`**（必须有主机名、不能带用户信息）或 **`mailto:` 单一地址**（不能带 `?subject=` 等参数）；最多 12 个；<br>- 顶部导航：站内链接必须以 `/` 开头，不能以 `//` 开头，**也不能指向 `/admin`、`/account`、`/auth`、`/api`、`/media`**；外部链接只接受 https；最多 10 个；<br>- 导航为空时，前台使用默认导航；<br>- 错误按 `links[i].field` 返回，界面可以定位到具体行 | API-DD §5.8；DD §8.2、§8.3“避免产生需要认证才能访问的公开导航目标” |
| 6 | **关于页** `GET/PUT /admin/pages/about`：<br>- 请求为 `{title, body_markdown}`，标题 1–160 字，正文最多 1 MiB；<br>- **保存即公开**：前端用醒目提示和二次确认说明这一点，不模仿文章的草稿与发布两阶段；<br>- 正文中的 `/media` 引用沿用文章的规则：用 goldmark 语法树提取，同样检查 READY 与非头像，并加锁，同时更新 `static_page_media`；被引用的图片公开且受删除保护，移除引用后恢复为私有；<br>- 纯文本写入 `body_plain_text`；<br>- 渲染使用与文章相同的安全渲染器（`html:false` 加地址白名单） | DD §8.4；UI/UX §7.8 |
| 7 | 每次修改设置、外链、导航或关于页都写入 `admin_audit_logs`，只记录字段名和数量，**不记录内容**；控制台的“管理动态”会显示这些记录 | PRD ADMIN-08；DD §8.5 |
| 8 | 媒体选择器：`GET /admin/media?usage_kind=` 支持用逗号分隔多个用途。选择器默认显示 `ARTICLE,SITE,PAGE`（不包括头像），因此已有的文章图片也能用作站点图片或关于页图片。<br>站点设置中上传的图片标为 SITE，关于页中上传的标为 PAGE | P3 媒体库复用；头像不可他用 |
| 9 | **分类与标签**：<br>- 补齐排序，用上移 / 下移按钮把 `sort_order` 重排为 10、20、30……；<br>- 支持编辑分类说明；<br>- 支持启用 / 停用，停用后不出现在前台的分类和标签列表中；<br>- 后台 API 不变（P4 已支持这些字段） | PRD ADMIN-03 |
| 10 | **后台统一**：<br>- 导航按 UI/UX §7.1 排列：控制台、文章、分类与标签、评论、用户、媒体库、网站设置、关于页；<br>- 宽度小于 768 px 时，导航改为由顶栏按钮展开的面板；<br>- 共用 `ConfirmDialog`，替换掉所有 `window.confirm`；<br>- 各页面都有骨架屏、空状态、错误状态与重试；<br>- 表格放在可横向滚动的容器中（容器设为 `position: relative`，避免绝对定位的辅助文本把页面撑宽）；<br>- 深色模式继续使用全站设计令牌 | UI/UX §7.1、§8；P7 阶段通过条件 |
| 11 | 前台读取的站点设置在 P7 生效：<br>- Favicon 加到每个页面的 `<link rel="icon">`；<br>- Logo 显示在顶栏站名前；<br>- 站名、个人栏、外链、导航和默认 SEO 由 P5 的 `/site` 接口提供；<br>- 后台保存后会清空前端缓存的站点数据，下一次页面跳转即可看到新内容 | PRD 4.2 |

## 后果

- 后台**没有创建管理员或修改角色的功能**，管理员只能通过服务器上的 `blog-admin create-admin` 命令创建（P2）。这符合“不得开放提升为 ADMIN 的 UI”，但需要在运维文档中说明（P8）。
- 外链图标只有 4 种。需要更多图标时，必须同时更新前台图标和 `site.IconKeys` 白名单。
- 用户登录后重新访问才会看到恢复后的账号状态，因为禁用时会撤销会话，用户必须重新登录。
