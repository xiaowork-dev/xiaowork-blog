# ADR-0006 — P6 评论系统、用户中心与评论治理实现决策

- 日期：2026-10-24
- 状态：已采纳（P6）
- 依据：PRD COMMENT-01~08、§6.3、§10；API-DD §4.1、§4.2、§4.4、§5.5、§5.6、§7、§8；DD §6.1、T05；UI/UX §5、§6.3、§7.5

**未修改任何数据表（迁移仍为版本 7）。** 接口全部来自 API-DD 已列出的路径。新增的错误码和可选字段如下，均向后兼容。

| # | 决定 | 依据 / 理由 |
|---|---|---|
| 1 | 评论读取接口：`GET /articles/{article_id}/comments`（`page`、`page_size`，默认 20、最大 50；`sort=latest\|oldest`）只对根评论分页。<br>每条根评论附带最多 2 条回复预览和 `reply_count`；`meta` 中包含 `comment_count`（公开评论总数）和 `comments_enabled`。<br>`GET /comments/{root_id}/replies` 按时间升序分页返回该楼全部回复。<br>文章不是 PUBLISHED（草稿、撤回、回收站）时，以上接口都返回 404 | API-DD §5.5、DD §6.1 分页口径 |
| 2 | 公开 `Comment` 字段与 API-DD §5.5 一致，另加：<br>- `reply_to {id, nickname}`：回复对象；<br>- `replies`：根评论的回复预览。<br>只有 VISIBLE 状态的评论返回 `body_text` 和 `author`。<br>隐藏或删除的评论在**仍有直接回复时**以占位形式保留（正文和作者为 null，前台显示“该评论已删除 / 已被隐藏”）；没有回复时不出现在公开列表中。<br>SQL 投影本身就不选出非公开正文，不依赖前端过滤 | API-DD §5.5“不得把原文泄漏在隐藏字段”；UI/UX §5.2“已有子回复时显示占位” |
| 3 | 发表：`POST /articles/{id}/comments` 发表根评论，`POST /comments/{id}/replies` 发表回复，权限为 U（已登录、邮箱已验证、账号正常）。<br>- 回复所属的文章和 `root_id` 由父评论推出，客户端无法指定，所以不可能跨文章回复；数据库的复合外键再兜底一次；<br>- 父评论被隐藏或删除时返回 409 **`COMMENT_NOT_REPLYABLE`**（新增错误码）；<br>- 在事务中对文章和公开快照加 `FOR SHARE` 锁，与发布、撤回互斥，避免在关闭评论的同时有新评论插入；<br>- 发表成功直接写入 VISIBLE，**没有任何审核状态** | DD T05；PRD COMMENT-02 |
| 4 | 正文规则（`CleanBody`）：<br>- 统一换行为 LF，制表符改为空格；<br>- 删除控制字符和不可见格式字符（如 bidi 覆盖、零宽空格），但保留 Emoji 中的 ZWJ/ZWNJ；<br>- 最多保留一个连续空行，去除首尾空白；<br>- 长度 1–2000 个字符。<br>正文按**纯文本**存储和返回；前台只用文本插值渲染，并识别 http(s) 链接（`rel="nofollow ugc noopener noreferrer"`）和 `@昵称`（只改样式，不生成链接）。不接受 HTML 和图片 | API-DD §5.5；PRD“纯文本、换行、Emoji 和安全链接” |
| 5 | 防滥用：<br>- 同一用户每分钟 5 次、每小时 20 次（复用 P2 的持久化限流，返回 429 并带 Retry-After）；<br>- 必须带 CSRF 令牌并通过 Origin 校验；<br>- 同一用户在同一文章 10 分钟内发表完全相同的内容，返回 409 **`DUPLICATE_COMMENT`**（新增，用于拦截重复提交和刷屏） | API-DD §7；PRD COMMENT-08 |
| 6 | 删除自己的评论 `DELETE /comments/{id}`：<br>- 服务端按会话中的用户 ID 再次核对所有权，非本人返回 403（`can_delete` 只是界面提示）；<br>- 删除时状态改为 DELETED_AUTHOR 并清空正文，回复保留；<br>- 重复删除仍返回 204；<br>- 文章撤回后，作者仍可删除自己的评论 | API-DD §5.5、§8 |
| 7 | 我的评论 `GET /me/comments`：<br>- 作者可以看到自己被隐藏评论的正文，并标注“已被管理员隐藏”；<br>- 文章不再公开时只返回 `available:false`，**不返回标题和链接**（避免泄露已撤回的内容） | UI/UX §6.3 |
| 8 | 评论治理：<br>- `GET /admin/comments` 支持按 `article_id`、`author_id`、`status`（含合并的 `DELETED`）、`from`/`to`（RFC 3339 时间点）、`q`（正文、昵称、邮箱关键词）筛选；管理员能看到作者邮箱和隐藏评论的正文；<br>- `hide` / `unhide` 返回 200，重复操作返回当前状态；对已删除的评论返回 409 **`COMMENT_STATE_CONFLICT`**（新增）；<br>- `DELETE` 改为 DELETED_ADMIN 并清空正文，不可恢复，返回 204；<br>- 隐藏、恢复、删除都写入审计日志，**日志不记录评论正文**；<br>- **没有审核队列，也没有“通过”按钮** | API-DD §4.4、§5.5；UI/UX §7.5；DD §8.5 |
| 9 | 用户资料 `PATCH /me/profile`：<br>- 请求为 `{"nickname"?, "bio"?}`，未传的字段保持不变，`bio` 为 null 或空字符串表示清空；<br>- 昵称沿用 P2 的规则（1–40 字符，不能有控制字符），简介最多 200 字（与 `user_profiles.bio` 一致），可以换行；<br>- 含未知字段时返回 400；每用户每小时最多 30 次。<br>`/auth/me` 新增 `bio` 字段。<br>头像、修改密码、更换邮箱、退出登录与退出所有设备都**直接复用 P2/P3 的接口**，没有另建账号体系 | API-DD §4.2；P6 要求“优先复用” |
| 10 | 修改密码后撤销包括当前会话在内的所有会话（P2 已采用“要求重新登录”），页面提示后引导用户重新登录。<br>更换邮箱时，确认链接必须在已登录原账号的浏览器中打开才能生效（P2 已实现），单独泄露链接不足以接管账号 | API-DD §5.6 |
| 11 | 评论区在**浏览器端加载**：文章 HTML 对所有读者都相同，不包含个性化的 `can_delete`；SSR 只输出评论区的框架。评论不承担 SEO 作用 | SAD §2.2；P5 的缓存策略 |
| 12 | 前台视觉上最多两级缩进：所有回复都放在根评论下的同一层，并显示“回复 @昵称”，数据库仍保存真实的父子关系。<br>提交失败时输入框保留原文。Ctrl+Enter 提交，Esc 取消回复。删除需要二次确认 | UI/UX §5.2；PRD COMMENT-03 |
| 13 | `/account/*` 页面由前端路由守卫跳转登录，同时发送 `X-Robots-Tag: noindex` 与 `private, no-store`（P5 已配置）；真正的权限判断在 Go API | API-DD §7 |

## 后果

- 限流使用 P2 的**固定一分钟窗口**。请求跨越窗口边界时，短时间内最多可通过两个窗口的配额（例如 10 条评论）；测试已按这一语义编写。若要严格的滑动窗口，需要另做设计。
- 没有回复的已删除或已隐藏评论会从公开列表中消失；管理员列表和作者的“我的评论”仍然保留它们。
- 禁用账号、管理员用户管理属于 P7；当前评论接口已能正确拒绝被禁用的账号（403 `ACCOUNT_DISABLED`）。
