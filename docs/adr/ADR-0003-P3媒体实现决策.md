# ADR-0003 — P3 本地媒体实现决策

- 日期：2026-10-23
- 状态：已采纳（P3）
- 依据：PRD MEDIA-01~08、SAD §8、DD §7 与 T06、API-DD §4.4/§5.7/§7、UI/UX §7.7

**未修改数据表；未删除或改变 API-DD 中的任何接口。** 新增内容均为向后兼容的可选项（见 #6、#7）。

| # | 决定 | 依据 / 理由 |
|---|---|---|
| 1 | 目录：`<MEDIA_ROOT>/originals/<2位>/<uuid>.<ext>`、`thumbnails/…`、`temp/`；存储键只由随机 UUID 生成，客户端文件名只作显示名（去路径、去控制字符、≤255 字节） | SAD §8.1；防覆盖与路径遍历；DB CHECK + 代码正则 + `filepath.Rel` 三重防护 |
| 2 | 上传流程：multipart 流式写入 `temp/`（O_EXCL、0600、边写边限长）→ 校验 → 生成缩略图 → `rename` 原子移入正式目录并 fsync 目录 → 最后写数据库；数据库失败则删除已移入文件（补偿），临时文件 1 小时后由清理任务删除 | DD §7.5、§8.3“先文件后记录、失败补偿” |
| 3 | 校验顺序：扩展名必须属于 jpg/jpeg/png/webp/gif 且与内容嗅探一致 → `DecodeConfig` 只读文件头检查尺寸（单边 ≤16384、像素 ≤ 上限）后才分配像素内存 → GIF 先扫描块结构计帧（≤500 帧、帧×像素 ≤ 5000 万）→ 完整解码 | API-DD §5.7“内容嗅探、解码及尺寸检查，防止文件名欺骗、压缩炸弹” |
| 4 | 默认上限：文章/站点/关于页图片 10 MiB、2000 万像素；头像 2 MiB、约 419 万像素（2048²）；均可通过 `MEDIA_MAX_BYTES/MEDIA_MAX_PIXELS/AVATAR_MAX_BYTES/AVATAR_MAX_PIXELS` 配置；同时最多 2 张图片解码；卷可用空间低于“预留 256 MiB + 3×单文件上限”时拒绝上传（Linux/macOS） | API-DD §5.7 建议默认值；API-30“磁盘空间不足时错误明确” |
| 5 | **原图逐字节保存，不重新编码、不剥离元数据**；静态图（JPEG/PNG/WebP）长边 >480 px 时另存缩略图（JPEG 源→JPEG q82，PNG/WebP 源→PNG）；GIF 不生成缩略图，始终返回原文件以保留动画 | PRD MEDIA-07“保留 GIF 动图行为，不得无提示破坏原图” |
| 6 | 缩略图通过 `GET /media/{id}/file?variant=thumb` 获取，权限与原图完全相同；无缩略图时回退为原图。缩略图路径由存储键推导，**不新增数据库字段** | API-DD §3.1“V1 内向后兼容地增加可选字段/参数” |
| 7 | 上传响应在 API-DD 示例字段之外增加 `thumbnail_url`、`original_filename`、`usage_kind`、`created_at`；列表另含 `uploaded_by`、`reference_count`；列表分页参数 `page/page_size/q/usage_kind` | 向后兼容的附加字段 |
| 8 | 读取授权：`READY` 且（被已发布文章正文/封面、站点设置、关于页、ACTIVE 用户头像引用）→ 匿名可读，`Cache-Control: public, max-age=300`；否则仅管理员或头像上传者本人可读，`private, no-store`；其余一律与“不存在”相同的 404 | API-DD §5.7、DD §7.1；短缓存使撤回在 5 分钟内生效 |
| 9 | 文件响应：数据库中的 MIME、`nosniff`、`Content-Disposition: inline`、`CSP: default-src 'none'; sandbox`、基于 SHA-256 的 ETag，支持 HEAD、Range、条件请求 | SAD §8.2 第 6 条“上传目录不可执行” |
| 10 | 删除状态机：事务 1 `SELECT … FOR UPDATE` 锁定媒体行（与引用表插入时的 FOR KEY SHARE 冲突）→ 统计全部引用通道 → 有引用返回 409 并给出各通道计数（不含私人内容）→ 无引用置 `PENDING_DELETE`；事务 2 再次加锁复查引用（若期间新增引用则恢复 `READY` 并返回 409）→ 删除缩略图与原图 → 置 `DELETED`。删文件失败时保留 `PENDING_DELETE`（不再提供访问），由后台任务每小时重试 | DD T06、API-DD §5.7“可重试补偿、不能误删并发引用” |
| 11 | 头像：`POST /me/avatar` 只修改调用者本人资料（请求中不接受任何目标字段），媒体记录与资料切换在同一事务；旧头像若已无引用则随即删除；每用户每小时 10 次 | API-DD §5.7、§7 |
| 12 | 管理员上传 `usage_kind` 只允许 ARTICLE/SITE/PAGE（AVATAR 只能经 `/me/avatar`）；每管理员每小时 120 次 | 权限隔离 |
| 13 | 一致性：后台任务与 `blog-admin media-check` 报告“有记录无文件”“有文件无记录”，**只报告不自动删除** | DD §11.2“首版不自动盲删无法判明归属的文件” |
| 14 | 上传与文件下载不再使用服务器级 Read/WriteTimeout，改为每请求 30 秒期限，上传/下载处理器延长到 2 分钟；JSON 接口仍有 15 秒处理超时 | 10 MiB 文件在慢速网络下 30 秒不够 |
| 15 | Linux 宿主机上 `.data/media` 必须属于 uid/gid 10001，否则 API 启动即失败并给出明确日志（P0 已在 README 说明） | 尽早暴露挂载错误，避免上传时才失败 |

## 未采纳 / 留待评审

- **EXIF/GPS 等元数据剥离**：会改变原图字节，与 MEDIA-07 冲突，且属于设计未要求的新功能。头像或照片中可能含拍摄位置等信息，**建议后续评审是否在上传时提示或剥离**。
- WebP 动画：所用解码器 `golang.org/x/image/webp` 不支持动画 WebP，预计此类文件会以“无法解码”被拒绝（**未专门测试**）；静态 WebP 已测试通过。
