# ADR-0001 — P1 数据库实现细化

- 日期：2026-10-23
- 状态：已采纳（P1）
- 依据：《数据库详细设计说明书》（DD）、《API 接口详细设计说明书》（API-DD）、PRD、SAD

## 背景

DD 定义了 24 张表、字段与主要约束，但部分物理细节（迁移工具接入、CHECK 的精确写法、种子数据、跨表一致性的数据库层保障）留给实施阶段。本 ADR 记录 P1 落地时的取舍。**未增删任何表或业务模块，未改变任何已确认的产品规则。**

## 决定

| # | 决定 | 依据 / 理由 |
|---|---|---|
| 1 | 迁移工具 goose v3.29.0，以 Go 库方式嵌入（`apps/api/db/migrations/*.sql` + `embed`），独立命令 `blog-migrate up/status/version/down`；Compose 增加一次性 `migrate` 服务，`api` 依赖其成功完成 | DD §11.3 推荐 goose；嵌入避免运行时依赖文件；PostgreSQL advisory 会话锁防止并发迁移 |
| 2 | 迁移按领域拆为 7 个有序文件（users/auth → media+profiles → taxonomy → articles → comments → site/audit → search），每个文件单事务、含 Down | IMP §3“不鼓励 24 张表写在一份不可回滚的 SQL” |
| 3 | `user_profiles` 与 `media_assets` 同在 00002 | 避免 users ↔ media 循环依赖（DD §4.2 已说明头像 FK 放资料表的原因） |
| 4 | UUID 主键无数据库默认值，由应用（`github.com/google/uuid`）生成 | DD §2“由可信应用层生成” |
| 5 | `article_publications(slug, article_id)` 复合 FK → `article_slugs(slug, article_id)`，并为此在 `article_slugs` 增加 `UNIQUE(slug, article_id)`；`article_publications.slug` 另建唯一索引 | 数据库层保证公开地址必然登记在同一文章名下（DD §5.4“唯一性的权威来源见 article_slugs”） |
| 6 | 草稿侧关联表 FK 指向 `article_drafts`，公开侧指向 `article_publications` | DD §5.7/5.8/7.2/7.3 原文；使“未发布文章写入公开标签”在 FK 层即被拒绝 |
| 7 | `users.email_normalized` CHECK：非空且等于 `lower(btrim(...))` | DD §4.1“产品级大小写不敏感”；不实现 Gmail 点号/加号合并（DD 明确禁止） |
| 8 | 令牌/会话摘要 CHECK `octet_length = 32` | DD §4.3/4.4“仅存 SHA-256 摘要”，防止误存明文 |
| 9 | `articles` 生命周期 CHECK：PUBLISHED/WITHDRAWN 必须有 `first_published_at`；TRASHED 必须有 `trashed_at`；`first_published_at` 与 `last_published_draft_revision` 同时为空或同时有值 | DD §5.1、T03、T04 |
| 10 | `article_publications` 标题、正文非空 CHECK | DD §5.2、API §5.3“发布要求标题/正文非空” |
| 11 | `comments`：除 DD 已列复合 FK 外，增加 CHECK——父/根成对出现、不可自回复、VISIBLE/HIDDEN 正文非空且 ≤2000 字符、DELETED_* 正文为 NULL 且有 `deleted_at`、HIDDEN 有 `hidden_at` | DD §6.1；2000 取 API §5.5 建议默认值。**如运营阶段调整评论长度上限，需新迁移修改该 CHECK** |
| 12 | `media_assets`：MIME 限于 JPEG/PNG/WebP/GIF；`storage_key` 禁止绝对路径、反斜杠与 `..` 段；`state='DELETED'` ⇔ `deleted_at` 非空 | DD §7.1、API §5.7 |
| 13 | `site_social_links.url` 仅 `https://` 与 `mailto:`；`site_navigation_links` INTERNAL 必须是站内相对路径（禁止 `//` 协议相对地址）、EXTERNAL 仅 `https://` | API §5.8；数据库作为纵深防御，API 仍需做完整校验 |
| 14 | `static_pages.page_key` CHECK 仅允许 `about` | DD §8.4“V1.0 仅 about，其他页面需再评审” |
| 15 | `site_settings` 在迁移中插入单例种子行（站名 `XiaoWork Blog`、个人名 `XiaoWork`，其他字段默认/空） | DD §8.1“部署初始数据创建”；不含任何秘密信息，后台可修改 |
| 16 | 分类/标签/文章 Slug 数据库只校验“非空、不含空白 `/ ? #`”，字符集与大小写规则交给 API | DD/API 未冻结 Slug 字符集（是否允许中文），避免数据库先行收紧 |
| 17 | 搜索：`pg_trgm` 扩展 + `article_publications` 的 title/summary/body_plain_text 三个 GIN trigram 索引 | DD §9.1；`pg_trgm` 为 trusted extension，库 owner 可创建。中文效果需 P5 用真实样本验收 |
| 18 | 外键全部使用默认 `NO ACTION`（无级联删除） | DD §2“优先 RESTRICT/NO ACTION，谨慎级联”；评论删除为墓碑，不做级联 |
| 19 | sqlc 1.31.0 通过官方 Docker 镜像运行（Windows 本机无 cgo），生成代码 `internal/store` 提交入库；CI 以 `sqlc diff` 防漂移 | ADR-003（pgx + sqlc） |

## 文档冲突检查

逐项对照 PRD / SAD / DD / API-DD 的数据相关内容，**未发现需要改变表结构的冲突**。已知的路径类差异（SAD 早期 `/uploads/*` 与 API-DD `/media/{id}/file`）不影响数据库，按 IMP §2.2 以 API-DD 为准。

## 后果

- 数据库层面即可拒绝跨文章回复、未登记 Slug 的公开快照、明文令牌、非法媒体路径等错误数据。
- 部分约束（评论长度、URL 协议）调整时需要新迁移，属于预期成本。
- 运行时账号与迁移账号目前相同（Compose 中均为 `POSTGRES_USER`）；DD §11.3 的最小权限分离在 P8 生产部署时落实。
