# ADR-0002 — P2 认证实现决策

- 日期：2026-10-23
- 状态：已采纳（P2）
- 依据：PRD AUTH-01~08 与 §8.1、SAD §6、DD §4 与 T01/T02、API-DD §3/§4.2/§5.6/§7、UI/UX §1.2/§6/§8

**未修改任何数据表，未新增或删除 API 契约中的接口。** 以下为设计文档留给实施阶段的细节取舍，以及一处文档间的路由不一致的处理。

| # | 决定 | 依据 / 理由 |
|---|---|---|
| 1 | Argon2id：m=19 MiB、t=2、p=1、16 字节盐、32 字节输出，参数写入哈希串便于日后升级；同时最多 4 个哈希并发（防内存耗尽） | SAD §6.1；OWASP Password Storage 基线；适配小规格 VPS |
| 2 | 未注册邮箱登录时对固定 dummy 哈希做一次校验，使“账号不存在”与“密码错误”耗时一致、错误码与文案一致 | PRD §8.1 防账号枚举 |
| 3 | 邮箱策略：**仅接受 ASCII 地址**；整个地址小写化作为唯一键（产品级大小写不敏感）；不做 Gmail 点号/加号合并 | DD §4.1 要求实现前明确 ASCII/IDN 策略；V1.0 选最简单且安全的方案，IDN 留待需求出现时再评审 |
| 4 | 会话：256 位随机令牌，库中只存 SHA-256；Cookie `__Host-blog_session`（https）/`blog_session`（仅 localhost http 开发），`HttpOnly; SameSite=Lax; Path=/`，有效期 14 天（`SESSION_TTL` 可配）；每次请求实时检查过期、撤销与账号状态 | API-DD §3.4；`__Host-` 前缀要求 Secure，故本地 http 开发不能使用该前缀 |
| 5 | CSRF：`GET /auth/csrf` 下发 HMAC-SHA256(APP_SECRET_KEY, 上下文) 令牌，上下文为“会话摘要”或“匿名 CSRF Cookie”；登录/退出自动轮换。所有写请求还须 `Origin` 等于 `PUBLIC_BASE_URL`，无 Origin 时须 `Sec-Fetch-Site: same-origin`，两者都无则拒绝 | API-DD §3.4 第 3 条“签名双提交 Cookie 并绑定会话/匿名上下文” |
| 6 | 限流持久化到 `auth_rate_windows`（固定窗口，主体为 HMAC 摘要，不存原始 IP/邮箱），阈值取 API-DD §7 建议值；登录“同邮箱失败 5 次/10 分钟”只统计失败；更换邮箱只统计真正发信的请求 | DD §4.5、API-DD §7 |
| 7 | 客户端 IP 只在直连方属于 `TRUSTED_PROXY_CIDRS` 时解析 `X-Forwarded-For`，并自右向左跳过可信跳点 | SAD §7.2、API-DD §2 |
| 8 | 修改密码后撤销**全部**会话（含当前），要求重新登录；重置密码同样撤销全部会话与未用重置令牌 | API-DD §5.6 推荐“要求重新登录” |
| 9 | 更换邮箱：新邮箱收到确认链接，确认时必须是同一账号的有效会话 + CSRF；确认后撤销其他设备会话和旧邮箱的重置令牌；邮件发送失败时立即作废令牌并返回 503 `MAIL_UNAVAILABLE` | API-DD §5.6、UI/UX §8“诚实提示” |
| 10 | 注册：邮件失败仍返回 201 + `email_delivery="unavailable"`（同步发送）；重发验证与找回密码统一返回 202 并**异步**发送，使存在/不存在的账号响应时间一致 | API-DD §5.6 |
| 11 | 首个管理员只能由运维命令 `blog-admin create-admin` 创建（密码从 stdin 读取），存在任意 ADMIN 后拒绝执行；不提供任何 HTTP 入口 | PRD §3、SAD §6.3；V1.0 单管理员 |
| 12 | `/api/v1/admin/*` 统一先经管理员守卫，再路由；未实现的管理接口对管理员返回 404，对普通用户 403、游客 401 | API-04；不提前实现 P4–P7 管理功能 |
| 13 | 邮件链接落在 Nuxt `/auth/verify?token=`（API-DD §5.6），同时保留 UI/UX §1.2 的 `/auth/verify-email` 作为重定向别名 | 文档优先级：API-DD 高于 UI/UX；两者都可用 |
| 14 | 更换邮箱确认页 `/auth/confirm-email?token=`（API-DD 未命名该页面，UI/UX 将入口放在 `/account/security`）；发起更换的表单随用户中心在后续阶段实现 | 本阶段只做认证流程必需的前端交互 |
| 15 | 本地开发邮件使用 Mailpit（`axllent/mailpit:v1.32.0`，仅 127.0.0.1:8025）；生产通过 `SMTP_*` 环境变量或 `SMTP_PASSWORD_FILE` 配置，`PUBLIC_BASE_URL` 非 localhost 时强制 TLS（starttls/tls） | 任务要求：测试不依赖公网邮箱，凭据不入库 |
| 16 | `/health/*` 的 `stage` 字段更新为 `P2` | P1 交付记录遗留项 |

## 后果

- 同一浏览器登录前取得的 CSRF 令牌在登录后失效，前端在登录/退出后需重新获取（`useApi` 已自动处理）。
- 本地 Compose 默认信任 `172.16.0.0/12`（含 Docker 网关），在本机可伪造 `X-Forwarded-For`；**生产部署（P8）必须把 `TRUSTED_PROXY_CIDRS` 收紧为 NPM 所在网络**。
- 邮箱若需支持国际化域名，需要新的评审与迁移策略（已有账号键不受影响）。
